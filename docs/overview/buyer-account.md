# Личный кабинет покупателя

> Личное пространство покупателя MUZILLA: заказы, покупки, избранное, коллекция, адреса доставки, отзывы, финансы (карты и история операций), чёрный список продавцов и настройки (логин, пароль, уведомления, мессенджеры). Технические детали — в разделе [Техническая часть](#техническая-часть).

## Назначение и роли

Личный кабинет (ЛК) — единая точка, где покупатель управляет своим аккаунтом, отслеживает заказы и деньги, ведёт коллекцию винила и настраивает уведомления. Один и тот же аккаунт может одновременно быть покупателем и продавцом — у продавца своя навигация, здесь описана только покупательская.

| Актор | Кто это | Что делает в ЛК |
|---|---|---|
| **Покупатель** | Авторизованный пользователь с подтверждённым телефоном | Все разделы ЛК: профиль, заказы, финансы, коллекция, избранное, адреса, отзывы, чёрный список, настройки |
| **Гость** | Неавторизованный пользователь | Видит только свою коллекцию (из localStorage); корзина и избранное тоже локальны и сливаются в аккаунт при входе |
| **Система** | Бэкенд Laravel + очереди | Валидация, отправка кодов (SMS/email), токенизация карт через Монету, webhooks мессенджеров, уведомления |

**Роли аккаунта** (флаги-чекбоксы в профиле): «Покупатель», «Продавец», «Коллекционер», «Коммерция», «Магазин». Роли не взаимоисключающие.

**Разделы навигации покупателя** (5 групп):

1. ЛК (`/profile`), Профиль (`/profile/edit`)
2. Корзина (`/cart`), Коллекция (`/profile/collection`), Избранное (`/wishlist`), Заказы (`/profile/orders`)
3. Покупки, Финансы (`/profile/finances`)
4. Адреса (`/profile/addresses`), Чёрный список (`/profile/blacklist`), Отзывы (`/profile/reviews`)
5. Настройки (`/profile/settings`)

## Доступ и защита страниц

Почти все страницы ЛК требуют авторизации и подтверждённого телефона (`middleware: ['auth', 'phone-verified']`). Есть исключения:

| Страница | Требуется вход | Требуется подтверждённый телефон |
|---|---|---|
| Профиль, редактирование, настройки, финансы, адреса, заказы, коллекция-управление | да | да |
| Чёрный список (`/profile/blacklist`) | да | **нет** |
| Мои отзывы (`/profile/reviews`) | да | **нет** |
| Коллекция (`/profile/collection`) — просмотр | **нет** (доступна гостю) | нет |

Гость, зашедший на защищённую страницу, редиректится middleware `auth`. Часть настроек (смена логина, пароля, уведомления, мессенджеры, верификация email) сознательно работает **без** `phone-verified` — иначе пользователь с ещё не подтверждённым телефоном не смог бы завершить настройку.

## 1. Профиль: просмотр и редактирование

**Просмотр** — `/profile`, **редактирование** — `/profile/edit`.

### Что показано

- Заголовок: «Имя Фамилия» (или имя аккаунта), бейдж «Профиль подтвержден» при верификации, кнопка «Стать продавцом» (ведёт на `/seller/register`), если пользователь ещё не продавец.
- Секции с полями, у каждой — **своя кнопка «Сохранить»**, которая появляется только когда в этой секции что-то изменилось.

### Поля по секциям

| Секция | Поля | Правила |
|---|---|---|
| **Данные** | Имя, Фамилия | Обязательны, до 60 символов, валидация «человеческого» имени (цифры/спецсимволы запрещены), проверка при потере фокуса |
| | Дата рождения | Только прошедшая дата (не в будущем) |
| | Город | Выбор через подсказки DaData |
| **Информация о себе** | О себе (bio) | До 1000 символов |
| **Роли** | 5 чекбоксов ролей | Boolean |
| **Приватность** | Скрыть ФИО, Скрыть телефон, Скрыть email | Boolean; управляют видимостью в публичном профиле |

Телефон и Email в профиле — **только для чтения**. Их меняют в Настройках (см. раздел 2) с подтверждением кодами.

### Флоу сохранения

1. Пользователь меняет поле → появляется кнопка «Сохранить» для этой секции.
2. Сохранение отправляет изменения на сервер, показывает toast об успехе.
3. При успехе обновляется идентичность пользователя в клиенте (без перезагрузки страницы).
4. Сервер валидирует данные, приводит типы, пересобирает отображаемое имя (`name` = «Имя Фамилия» для покупателя; у продавца `name` = название магазина — не трогается), фиксирует время последней активности.

## 2. Настройки

Страница `/profile/settings` состоит из блоков: **Логин** (email/телефон + верификация email), **Безопасность** (пароль), **Уведомления** (матрица каналов), **Мессенджеры** (Telegram / MAX).

### 2.1. Смена email и телефона (с подтверждением кодами)

Логин меняется только через двойное подтверждение — старые контакты защищены кодами на новые.

**Пошагово:**

1. Кнопка «Изменить» разблокирует поля email и телефона. Система сама определяет, что реально изменилось (телефон сравнивается по цифрам).
2. «Отправить код» — сервер проверяет, что хотя бы одно поле изменилось (иначе ошибка «Нет изменений»), проверяет уникальность нового email, кладёт «ожидающие» значения во временное хранилище на **10 минут** и отправляет коды: SMS на новый телефон и/или код на новый email. Возвращается таймер повторной отправки.
3. Появляются поля ввода кодов — SMS-код показывается только если менялся телефон, email-код — только если менялся email. Каждый код 6-значный.
4. «Подтвердить» — сервер сверяет введённые коды с ожидающими значениями. Кнопка «Сохранить» становится активной, только когда подтверждены **все** изменённые каналы.
5. «Сохранить» — сервер повторно проверяет флаги подтверждения, применяет новый телефон и/или email. **Новый email при этом помечается неподтверждённым** — потребуется отдельная верификация (см. 2.4). Временные данные и коды очищаются, идентичность пользователя обновляется.

**Повторная отправка** доступна после истечения таймера («Получить новый код»).

### 2.2. Смена пароля

**Пошагово:**

1. Ввести новый пароль и повтор (минимум 4 символа, показ по «глазу»).
2. «Отправить код подтверждения» — на телефон профиля уходит SMS-код.
3. Ввести 6-значный код → «Подтвердить» (на этом шаге проверяется только клиентский флаг, сервер не дёргается).
4. «Сменить пароль» — сервер проверяет совпадение телефона с профилем, верифицирует код и сохраняет новый пароль.

### 2.3. Уведомления (матрица категории × каналы)

Матрица тумблеров: строки — категории событий, столбцы — каналы доставки. При первом заходе строка настроек создаётся автоматически с дефолтами.

**Каналы:** Email · В приложении · Telegram · MAX.

| Категория | Email | В приложении | Telegram | MAX | По умолчанию |
|---|:---:|:---:|:---:|:---:|---|
| **Заказы** | ✓ | ✓ | ✓ | ✓ | Email + В приложении включены |
| **Сообщения** (email не чаще 1/5 мин) | ✓ | ✓ | ✓ | ✓ | Email + В приложении включены |
| **Список желаемого** | ✓ | ✓ | ✓ | ✓ | Email + В приложении включены |
| **Выплаты** | ✓ | ✓ | ✓ | ✓ | Email + В приложении включены |
| **Новости / акции** (маркетинг) | ✓ | — | ✓ | ✓ | Всё выключено |

У категории «Новости / акции» **нет** канала «В приложении». На UI подпись: «Email-уведомления приходят только на подтверждённый адрес».

### 2.4. Верификация email

Если email не подтверждён, в блоке «Логин» подсвечивается «Не подтвержден — подтвердить». Клик открывает модалку верификации; после успеха обновляется идентичность и показывается toast.

### 2.5. Привязка мессенджеров Telegram / MAX

**Пошагово:**

1. «Привязать» — сервер создаёт одноразовый токен (живёт **15 минут**) и возвращает deep-link на бота (`https://t.me/{бот}?start={токен}` или аналог для MAX).
2. Клиент открывает бота по ссылке, показывает toast «Перейдите в бота и нажмите Старт».
3. Пользователь жмёт «Старт» → бот присылает токен на webhook → сервер находит пользователя по токену (**токен сгорает при первом использовании**) и записывает идентификатор чата и время привязки.
4. **Отвязка** обнуляет идентификатор. Статус «Привязан» = идентификатор заполнен.

## 3. Финансы

Страница `/profile/finances`: **Привязанные карты** и **История операций**.

### 3.1. Привязанные карты

Каждая карта показывается с иконкой платёжной системы (Мир / Visa / Mastercard), маской, меткой «По умолчанию» или «Истёк срок».

**Привязка новой карты:**

1. «Привязать карту» → сервер создаёт платёж-заглушку на **1 ₽** с флагом сохранения карты и редиректит на страницу оплаты Монеты.
2. После оплаты webhook и фоновая задача сохраняют токенизированную карту; 1 ₽ возвращается отдельной задачей возврата.
3. Если платёжка недоступна (пустой URL) — toast «Скоро / после активации платёжной системы».

**Удаление:** крестик по наведению → подтверждение → удаление (сервер проверяет принадлежность карты пользователю).

### 3.2. История операций

Сводит **платежи** покупателя (по завершённым оплатам его заказов) и **возвраты** (успешные) в единый список, отсортированный по дате (новые сверху).

- **Табы:** Все / Оплата / Возврат.
- **Периоды:** Всё время / Неделя / Месяц / Квартал / Год.
- Возвраты отображаются со знаком «+» и зелёным цветом.
- Показываются только операции по заказам, где покупатель — текущий пользователь (изоляция чужих данных).
- Незавершённые платежи в список не попадают.

## 4. Избранное (Wishlist)

Страница `/wishlist` (старый путь `/profile/favorites` редиректит сюда).

**5 типов избранного** (продавцов в избранном нет — для продавцов есть обратная сущность, «чёрный список», раздел 6):

| Тип | Что это |
|---|---|
| Товары | Карточки товаров продавцов |
| Артисты | Исполнители из дискографии |
| Релизы | Конкретные издания |
| Мастер-релизы | Мастер-записи (группа изданий) |
| Лейблы | Издающие лейблы |

**Возможности:** добавить/убрать, переключить (toggle), проверить наличие, счётчики по типам, массовые операции, экспорт в JSON. Добавление и toggle защищены ограничением частоты запросов.

**Гость → аккаунт:** гостевое избранное хранится в localStorage; при входе оно сливается с аккаунтом (объединение, без дублей). Для гостевой страницы есть публичная гидрация избранного по списку идентификаторов.

**Уведомления:** когда релиз из списка желаемого появляется в продаже, срабатывает категория «Список желаемого» (см. 2.3).

## 5. Адреса доставки (способы доставки покупателя)

Страница `/profile/addresses`, заголовок «Способы доставки» — это адреса/ПВЗ, **куда привезти** заказ покупателю.

**Поля метода:** тип (пункт выдачи / курьер), перевозчик (Почта России, СДЭК и т.п.), название ПВЗ, индекс, полный адрес, «по умолчанию», город (по умолчанию из профиля). Подпись метода: для ПВЗ — «название · индекс», для курьера — полный адрес.

**Действия:** список → radio «по умолчанию», иконки «Копировать» (в буфер + создаёт копию метода с `по умолчанию = нет`), «Редактировать» (модалка), «Удалить» (с подтверждением). Добавление — модалка с подсказками DaData. Все операции защищены проверкой прав (нельзя трогать чужой адрес).

::: tip Удаление адреса «по умолчанию»
При удалении дефолтного адреса система автоматически назначает дефолтным следующий (самый старый) адрес.
:::

## 6. Чёрный список (блокировка продавцов)

Страница `/profile/blacklist` (доступна без подтверждённого телефона). Список заблокированных с аватаром, кнопкой «Убрать из ЧС» (с подтверждением) и ссылкой на профиль.

**Где блокируют:** не на этой странице, а из **профиля продавца** (`/u/{id}`) — кнопкой блокировки; статус читается отдельным запросом.

**Крайние случаи (сервер):**

| Ситуация | Результат |
|---|---|
| Заблокировать самого себя | Ошибка «Вы не можете заблокировать самого себя» |
| Повторная блокировка | Ошибка «уже заблокирован» |
| Несуществующий пользователь | Не найден |
| Разблокировать не заблокированного | Ошибка |

## 7. Мои отзывы

Страница `/profile/reviews` (доступна без подтверждённого телефона). Показывает отзывы, оставленные текущим пользователем.

- **Редактирование** и **удаление** (мягкое, с подтверждением) — только своих отзывов (проверка авторства).
- **Поля отзыва:** оценка, комментарий, ответ продавца, отметка «подтверждённая покупка», анонимность, автор, товар, продавец, дата.

**Создание отзывов — только из заказа.** Свободное создание отзыва удалено: отзыв оставляется из карточки заказа (кнопка «Оставить отзыв» при наличии права `can_review`). По успешному заказу — отзыв на продавца и товары, по неуспешному — только на продавца.

## 8. Коллекция (и импорт из Discogs)

Страница `/profile/collection` — личная коллекция винила. Доступна **гостю** (из localStorage); управление требует входа.

**Поля записи коллекции:** название, артист, лейбл, каталожный номер, формат, год, страна, жанр, стиль, состояние носителя и конверта (грейды M…P), обложка, цена покупки, количество, видимость, связь с релизом Discogs.

**Действия:** поиск, «выбрать все» + массовое удаление, пагинация, раскрытие деталей, редактирование, переключение видимости (по записи и массово «Скрыть/Показать коллекцию в профиле»), «в избранное» (требует связи с релизом — иначе предупреждение), изменение количества (1…999), «Продать» (модалка создаёт товар; после продажи количество уменьшается или запись удаляется), «У других продавцов» (переход в каталог по релизу).

**Гость:** коллекция читается из localStorage, поиск и пагинация на клиенте; продажа/видимость/импорт/количество требуют входа (toast). При входе гостевая коллекция сливается с аккаунтом.

**Импорт — два пути:**

1. **CSV из экспорта Discogs** — модалка «Добавить коллекцию»: загрузка `.csv` (до 10 МБ), сервер возвращает число импортированных записей.
2. **По ID через `/profile/discogs-import`** — диагностический импорт одной сущности (релиз/артист/лейбл/мастер) по идентификатору Discogs. Статусы `pending / processing / completed / failed`, автообновление каждые 30 с, повтор для упавших, удаление (кроме тех, что в обработке), карточки статистики.

## 9. Заказы и покупки

Страницы `/profile/orders` (список) и `/profile/orders/{id}` (детали).

- **Табы:** Активные / Завершённые. Поиск по товарам, период, сортировка.
- **Карточка:** дата, товар, сумма, номер заказа, статус оплаты, статус заказа, «Детали заказа», «Оставить отзыв» при наличии права.
- Видны только заказы текущего покупателя.
- **Жизненный цикл заказа:** подтверждение продавца 48 ч (иначе автоотмена и возврат) → QR → доставка → выплата продавцу через 48 ч после доставки, с паузой при споре. Оплата — Монета (карта / СБП / сохранённая карта).

Подробнее — [Заказы](/overview/orders).

## Уведомления

Отправляются по матрице настроек (раздел 2.3). Сводно:

| Событие | Категория | Каналы (если включены) |
|---|---|---|
| Изменения по заказу (подтверждение, QR, доставка, отмена) | Заказы | Email · В приложении · Telegram · MAX |
| Новое сообщение | Сообщения | Email (≤1/5 мин) · В приложении · Telegram · MAX |
| Релиз из списка желаемого появился в продаже | Список желаемого | Email · В приложении · Telegram · MAX |
| Движения по выплатам | Выплаты | Email · В приложении · Telegram · MAX |
| Новости и акции | Новости | Email · Telegram · MAX (без «В приложении») |

Email уходит только на подтверждённый адрес.

## Правила и особенности

- Отображаемое имя покупателя собирается автоматически из «Имя Фамилия»; у продавца имя = название магазина.
- Смена email и телефона всегда требует подтверждения кодами; новый email после смены неподтверждён.
- Приватность (скрыть ФИО/телефон/email) влияет на публичный профиль.
- Гостевые корзина, избранное и коллекция хранятся локально и сливаются в аккаунт при входе.
- Финансовая история и заказы строго изолированы по текущему пользователю.
