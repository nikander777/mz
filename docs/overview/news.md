# Новости и блог

> Контентный раздел площадки: публичная лента новостей и материалов (анонсы, статьи, акции) плюс полноценный админ-CRUD с публикацией, архивом, корзиной и массовыми операциями. Технические детали — приложение [Техническая справка → API: новости](/api/news-models).

## Назначение и роли

«Блог» и «Новости» — это один раздел (отдельной сущности «блог» в системе нет; лента живёт по адресу `/news`). Разделены два контура: **публичный** (только чтение опубликованного, без авторизации) и **админский** (создание, редактирование, публикация, архивирование, удаление и восстановление — под правами `news.*`).

| Актор | Что может |
|---|---|
| **Гость / любой посетитель** | Читает опубликованные новости: лента, деталь, «последние», «популярные», категории/теги, связанные материалы. Авторизация не нужна. |
| **Автор / редактор (админка)** | Создаёт и редактирует новости, грузит обложку и галерею, задаёт категории/теги/SEO, публикует и архивирует. Требуются права `news.create`, `news.edit`, `news.publish`, `news.archive`. |
| **Администратор** | Всё вышеперечисленное + удаление в корзину, восстановление, окончательное удаление, массовые операции. Права `news.delete`, `news.view` и остальные `news.*` выданы ролям `admin`/`super`. |

## Что показано (публичная часть)

- Блок **«Последние новости»**: одна крупная карточка + три боковых + кнопка «Больше материалов» (ведёт на ленту, отсортированную по популярности).
- **Лента «Новости»** с сортировкой (по популярности / по дате) и фильтрами по категории, тегу, поиску.
- Селектор **«Показать по»**: 20 / 40 / 60 / 100 и пагинация.
- **Детальная страница** новости: заголовок, дата, время чтения, кнопка «Поделиться», галерея (или обложка), тело материала (рендер Editor.js), автор, соцкнопки (Telegram / VK / X), сайдбар «Самое важное» и блок «Другие новости».

## Пошаговый флоу

### 1. Публичная лента (`/news`)

1. Страница делает два запроса при загрузке: «последние 4» (для верхнего блока) и основную ленту с параметрами `page`, `per_page`, `sort`.
2. Отображаемое состояние:
   - идёт загрузка → спиннер;
   - **ошибка API** → блок «Ошибка загрузки» + кнопка «Попробовать снова»;
   - есть данные → сетка карточек + пагинация (если страниц больше одной);
   - данных нет → **«Новостей пока нет»** (пустая лента без ошибки).
3. Фильтры: смена «Показать по» или сортировки сбрасывает страницу на первую. Пагинация — постранично (со скроллом к началу ленты) либо «Загрузить ещё» (следующая страница дописывается).
4. В ленту попадают **только опубликованные** новости: статус `published`, `published_at` заполнен и наступил (не в будущем).

### 2. Детальная страница (`/news/{slug}`)

1. При открытии загружаются: сам материал по slug, связанные новости и популярные (для сайдбара).
2. Если материал не найден или отдал ошибку → **«Новость не найдена»** + ссылка назад в ленту.
3. Иначе рендерится полный материал: заголовок, дата и время чтения, кнопка «Поделиться» (системное окно `navigator.share`, а при отсутствии — копирование ссылки в буфер), галерея с точками-навигацией (или обложка, если галереи нет), тело через рендер Editor.js, автор, соцкнопки, сайдбар «Самое важное» и блок «Другие новости» (с клиентскими стрелками-пагинацией).
4. **Каждый заход на деталь увеличивает счётчик просмотров** и обновляет отметку последнего просмотра.
5. SEO-теги берутся из блока `seo_meta`, а при его отсутствии — из заголовка, лида (`excerpt`) и обложки.

### 3. Публикация из админки (`/admin/news`)

1. При открытии формы проверяются права (`news.create` для создания, `news.edit` для правки); без прав — редирект в список.
2. Форма: заголовок (при создании автоматически подставляет slug), slug, лид, тело (Editor.js), статус, обложка, дата публикации, категории, теги, медиа, SEO.
3. **Сохранение**: клиент проверяет, что заполнены заголовок и тело; собирает данные и отправляет. Создание — POST, правка — PUT. Успех → возврат в список + уведомление-тост.
4. **Ветки по статусу**:
   - статус `published` без указанной даты → дата публикации проставляется автоматически на «сейчас» (и на уровне запроса, и на уровне модели);
   - `draft` — черновик, в публичной ленте не виден;
   - `archived` — снят с публикации, в ленте не виден.
5. Автоматика при сохранении (модель): генерируется slug из заголовка (с суффиксом `-N` при коллизии), считается время чтения (≈ слова / 200, минимум 1 минута), проставляется дата публикации при первой публикации.
6. В списке админки: кнопка «Опубликовать» видна только у черновика, «Архивировать» — только у опубликованного, «Удалить» — с диалогом подтверждения (одиночно или массово).

## Уведомления

| Событие | Кому | Канал |
|---|---|---|
| Публикация / архив / удаление новости | — | **Нет** |

Раздел новостей **не отправляет никаких уведомлений** — ни email, ни Telegram / Max, ни push, ни внутренних событий или фоновых задач. Публикация материала никого не оповещает; единственный побочный эффект — запись в журнал действий администратора (для админских операций) и служебное логирование.

## Все сценарии и крайние случаи

| Ситуация | Что происходит |
|---|---|
| **Пустая лента** | Публичный список возвращает пустой набор, пагинация скрыта, фронт показывает «Новостей пока нет». |
| **Черновик / архив по прямому URL** | Деталь требует статус `published` → **404**, фронт «Новость не найдена». |
| **Несуществующий slug** | **404** → «Новость не найдена». |
| **Фильтр по категории/тегу** | Публично — по slug (`?category=`, `?tag=`), в админке — по id. Несуществующий slug/id → пустой результат, не ошибка. |
| **Коллизия slug** | Автогенерация добавляет `-1`, `-2`…; ручной дубль slug → **422** (уникальность). |
| **Связанные без ручных связей** | Добираются из той же категории; если и категорий нет — блок пуст (скрыт). |
| **Восстановление не удалённой новости** | **422** «не в корзине». |
| **Массовая операция над «уже в статусе»** | Пропускается, счётчик изменённых не растёт. |
| **Окончательное удаление** | Физически удаляет запись + файлы обложки и галереи. |
| **Загрузка галереи** | Файлы пишутся на диск, размеры считаются автоматически, порядок — в конец. |
| **Время чтения не задано** | Фронт подставляет запасные 5 минут; бэкенд считает минимум 1. |
| **Кэш статистики** | Публичная статистика кэшируется до 5 минут — свежая публикация в ней появляется с задержкой. |

## Статусы новости

| Статус | Значение |
|---|---|
| **Черновик** (`draft`) | Создан, не опубликован. В публичной ленте и по прямому URL недоступен. По умолчанию у новой записи. |
| **Опубликован** (`published`) | Виден в ленте (если дата публикации наступила) и по прямому URL. |
| **Архив** (`archived`) | Снят с публикации, в ленте и по прямому URL недоступен; дата публикации сохраняется. |
| **В корзине** (soft delete) | Мягко удалён, в публичной части не виден, доступен в админке для восстановления или окончательного удаления. |

## Правила и особенности

- Публичная лента показывает материал только при трёх условиях сразу: статус `published`, дата публикации заполнена и уже наступила.
- Тело материала (`content`) отдаётся публично **только на детальной странице**, в ленте его нет (экономия трафика).
- Slug генерируется автоматически из заголовка при создании; при правке существующий slug не перегенерируется.
- Время чтения и дата публикации проставляются автоматически (см. флоу).
- Публичная статистика (агрегаты) кэшируется ~5 минут.
- Права на операции разделены: просмотр/создание/правка/публикация/архив/удаление — отдельные разрешения `news.*`.
