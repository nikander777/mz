# Доставка

> Как заказ доезжает от продавца до покупателя: расчёт стоимости и срока, выбор пункта выдачи на карте, автоматическое оформление отправления (накладная / QR), трек-номер и отслеживание вплоть до статуса «Доставлено» (который запускает выплату продавцу). Технические детали (провайдеры, поллинг, накладные) — приложение [Техническая справка → Доставка](/processes/delivery).

::: warning Расчёт стоимости доставки
- **Музыкальные носители** — предлагаем единый базовый размер посылки, в который вписывается любой носитель (например, **1 кг, 30×30×10 см**); продавцу вводить ничего не нужно.
- **Hi-Fi — на обсуждение.** Стоимость сильно зависит от веса и габаритов, но у **импортированных лотов этих данных нет**. Нужно решить: **обязываем ли продавцов указывать вес и габариты** в карточке товара — и **что делать с уже импортированным каталогом**, где этих данных нет?
:::

## Назначение и роли

Подсистема решает четыре задачи: (1) расчёт стоимости и срока по перевозчикам; (2) поиск пунктов выдачи (ПВЗ) для карты при оформлении; (3) создание отправления (заявка + трек + QR/накладная) в момент подтверждения заказа продавцом; (4) периодический опрос статуса до «Доставлено» — именно доставка запускает окно выплаты продавцу.

| Роль | Что делает |
|---|---|
| **Покупатель** | Выбирает способ доставки и пункт выдачи при оформлении — отдельно по каждому продавцу |
| **Продавец** | Настраивает свой **пункт отправки** (ОПС Почты / ПВЗ СДЭК), подтверждает заказ, передаёт посылку и отмечает отправку |
| **Площадка** | Оформляет отправление у перевозчика, опрашивает статус, обновляет заказ, шлёт уведомления |
| **Перевозчики** | Почта России и СДЭК |

::: warning Почта России
Мы пока не убирали ее полноценно с портала. Мы раз в неделю продолжаем создавать новые заявки. Если к моменту финального запуска у нас ничего не получится, мы в течение 1-2 дней удалим все упоминания Почты России.
:::


## Перевозчики

- **Почта России** — подключена по умолчанию, основной способ отправки. Расчёт по публичному тарифу, оформление через Otpravka API, отслеживание по SOAP.
- **СДЭК** — расчёт, выбор ПВЗ на карте, оформление по тарифу 136 (склад→склад, ПВЗ→ПВЗ). Трек и накладная догружаются асинхронно.

## Пошаговый флоу

### 1. Оформление (заготовка отправления)

Покупатель выбирает способ доставки и **пункт выдачи** — отдельно по каждому продавцу; стоимость и срок рассчитываются автоматически. При оформлении создаётся заготовка отправления со статусом «Ожидает отправки»: зафиксированы перевозчик, способ, стоимость и оценочный вес. Трека и QR ещё нет.

### 2. Оплата → ожидание подтверждения продавцом

После оплаты заказ становится «Оплачен», продавцу приходит уведомление «подтвердите заказ за 48 часов». QR/накладной по-прежнему нет — они появляются только после подтверждения.

### 3. Подтверждение заказа продавцом (формируется отправление)

Продавец подтверждает заказ → «Оплачен» переходит в «В обработке» → запускается автоматическое создание отправления: у перевозчика (Почта России или СДЭК) создаётся заявка, в заказ подставляются трек-номер, штрихкод, QR/накладная, выбранный ПВЗ; продавцу уходит уведомление «готово к отправке» (с QR-кодом, накладной и выбранным отделением).

Создание отправления идёт в фоне (очередь) с 3 повторами. Если задача исчерпала попытки — отправление помечается «Ошибка» и попадает под ручной/командный повтор.

### 4. Отправка продавцом

Продавец передаёт посылку → «В обработке» переходит в «Отправлено», покупатель получает трек-номер, начинается отслеживание. Мы опрашиваем обновления статусов раз в час, поэтому заказ перейдет в Отправлено не моментально. 

### 5. В пути → Прибыло в ПВЗ → Доставлено

Статус обновляется автоматически: система периодически опрашивает перевозчика (СДЭК/Почта). При прибытии в ПВЗ покупателю приходит уведомление. При статусе «Доставлено» заказ закрывается и запускается окно выплаты продавцу (см. [Заказы](/overview/orders) и [Выплаты продавцу](/business/seller-payouts-flow)).

**Пункт отправки продавца** настраивается в кабинете (раздел «Пункты отправки»); первый добавленный ОПС Почты привязывается ко всем опубликованным товарам без пункта отправки. Дефолтный пункт хранится **раздельно на каждого перевозчика** — у продавца может быть одновременно дефолтное отделение Почты и дефолтный ПВЗ СДЭК.

## Расчёт стоимости и срока

- **Почта России / СДЭК** — расчёт выполняется, если переданы оба почтовых индекса (откуда и куда). Почта — публичный тариф + сроки ЕКОМ; СДЭК — калькулятор тарифа 136.
- При сбое API расчёт оформление заказа **не возможно**.

## Пункты выдачи на карте

Карта checkout подбирает ПВЗ в трёх режимах (по приоритету): по видимой области карты (bbox) → по координатам центра → по названию города. Дополнительно можно фильтровать по перевозчикам.

- **СДЭК** — точки берутся из локального каталога ПВЗ (наполняется ежедневной синхронизацией с СДЭК); при подборе по городу, если API недоступно, используется локальный каталог.
- **Почта** — точки запрашиваются у API по координатам (с кешированием).

Если не передан ни один режим подбора (нет bbox, города и координат) — запрос отклоняется с ошибкой валидации.

## Уведомления

| Событие | Кому | Каналы |
|---|---|---|
| Оплачено, ждём подтверждения продавца (48 ч) | Продавец | сайт + email + месенджеры (опционально) |
| Продавец подтвердил — отправление, QR и накладная готовы | Продавец | сайт + email (QR-код картинкой, накладная PDF)  |
| Прибыло в ПВЗ | Покупатель | сайт + email + месенджеры (опционально)  |
| Отправлено | Покупатель | сайт + email + месенджеры (опционально) |
| Доставлено | — | запускает окно выплаты продавцу |

Каналы (email / Telegram / Max) резолвятся по настройкам пользователя.

## Все сценарии и крайние случаи

| Ситуация | Что происходит |
|---|---|
| Оформление | Создаётся заготовка отправления «Ожидает отправки»; трека/QR ещё нет |
| Подтверждение (Почта/СДЭК) | Создаётся заявка, подставляются трек/QR/накладная, уведомление продавцу |
| Сбой создания заявки (после 3 попыток) | Отправление → «Ошибка»; ждёт повтора командой `cdek:retry-failed-shipments` |
| СДЭК: трек/накладная не успели прийти | Трек временно = внутренний UUID, накладной нет; добираются фоновой задачей (окно 3 дня) |
| СДЭК: у получателя не выбран ПВЗ | Заявку создать нельзя → «Ошибка» |
| СДЭК: продавец не настроил пункт отправки СДЭК | Заявку создать нельзя → «Ошибка» |
| Почта: невалидный индекс/город/ФИО получателя | Заявку создать нельзя → «Ошибка» |
| Повторное подтверждение (гонка) | Если трек уже есть — создание пропускается |
| Прибыло в ПВЗ (первый раз) | Уведомление покупателю; повторный проход событие не дублирует |
| Доставлено | Заказ → «Доставлено»; запускается окно выплаты продавцу (delivered_at + 48 ч, пауза при споре) |
| Отмена заказа | Заявка у перевозчика отменяется (СДЭК — только до передачи в доставку); сбой отмены не критичен |
| Расчёт при недоступном API | Блокировка оформления заказа |

## Статусы доставки

Ожидает отправки · Готово к отправке · Отправлено · В пути · Прибыло в ПВЗ · Доставлено · Возврат · Отменено · Ошибка. Финальные статусы — «Доставлено», «Возврат», «Отменено». Полный справочник — [Справочник статусов](/overview/statuses).

## Правила и особенности

- Отправление создаётся автоматически при подтверждении заказа продавцом (Почта России и СДЭК).
- Дефолтный пункт отправки хранится **раздельно на каждого перевозчика**; первый добавленный ОПС Почты / СДЭК привязывается ко всем товарам без пункта отправки.
- У СДЭК отправитель = ПВЗ продавца (пункт отправки СДЭК); ФИО и телефон отправителя — всегда продавца.
- Отслеживание — периодическим опросом (Почта/СДЭК каждые 60 мин, добор данных СДЭК — каждые 15 мин); не мгновенное.
- Вес всегда оценочный, нужно определиться с разделом Hi-Fi и базовыми габаритами.
- «Доставлено» — единственный статус, закрывающий заказ и запускающий выплату.

## Техническая часть

Провайдеры (СДЭК API v2 — OAuth, ПВЗ, калькулятор тарифа 136, заказы, накладные, трекинг, отмена; Почта России — Otpravka + публичный тариф + SOAP-трекинг), оркестратор доставки, локальный каталог ПВЗ СДЭК, поллинг статусов, добор данных, обработка статусов и уведомлений — приложение [Техническая справка → Доставка](/processes/delivery).
