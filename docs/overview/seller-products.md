# Работа с товарами (продавец)

> Как продавец выставляет и ведёт товары: добавление, заполнение карточки, фото, статусы, продажа из коллекции. Один из ключевых процессов площадки.
> Технические детали — приложение [Техническая справка → Продажа товара](/processes/seller-listing).

## Назначение и роли

Продавец создаёт и ведёт свои товары в кабинете (`/seller/products`). Товары бывают двух типов: **Музыка** (винил/CD/кассеты/DVD — с **опциональной** привязкой к [дискографии](/overview/discography)) и **Hi-Fi аппаратура**.

Отдельной сущности «продавец» в коде нет: продавцом считается любой пользователь с флагом `is_seller` и **подтверждённым телефоном**. Публикация в каталоге открывается после того, как продавец **подключит выплаты** (заключит договор с НКО МОНЕТА через анкету в кабинете) — см. ниже. Ручного одобрения продавца администратором нет.

| Актор | Что может | Ограничения |
|---|---|---|
| Продавец (владелец) | Создавать, смотреть, редактировать, удалять, восстанавливать **свои** товары | Только свои (`product.user_id === user.id`); нужен подтверждённый телефон |
| Продавец без подключённых выплат | Всё то же — создавать и вести товары | Товары **не показываются** в каталоге, пока не подключены выплаты |
| Другой продавец | Ничего с чужими товарами | `403` на просмотр/редактирование/удаление чужого товара |
| Пользователь без подтверждённого телефона | Ничего в кабинете продавца | Блок middleware (`403`/redirect) на всех `/api/profile/products/*` |
| Не-продавец | Не заходит в кабинет | Фронт при `onMounted` уводит на `/profile` |

## Условие публикации: подключение выплат

Продажи открываются, когда продавец **подключит выплаты** — заключит договор с НКО МОНЕТА через анкету в кабинете. Ручного одобрения или модерации продавца администратором нет: как только выплаты подключены, продавец допущен к продажам. До этого товары можно создавать и вести, но они **не публикуются** в каталоге и заказ по ним оформить нельзя (в кабинете висит плашка о том, что до подключения выплат товары не публикуются). Подробнее — [Выплаты продавцу](/overview/payouts).

Витрина каждый раз пересчитывает видимость товара по фильтру поиска (Meili): товар виден, только если одновременно опубликован (`status=active`), есть в наличии (`in_stock=true`), указан пункт отправки (`has_pickup=true`) и продавец **допущен к продажам** (выплаты подключены). 

## Флоу: добавить товар

1. Кабинет продавца → **«Каталог товаров»** → кнопка **«Добавить товар»** → выбор типа (**Музыка** или **Hi-Fi**) → переход в форму.
2. Форма при открытии подгружает нужную категорию (для музыки — по slug `music`) и список **пунктов отправки (ПВЗ)** продавца, автоматически подставляя ПВЗ по умолчанию.
3. Для музыки — **(опционально)** найти релиз в дискографии Discogs: тогда артист, год, формат, лейбл, каталожный номер, страна, жанр, обложка подтянутся автоматически (поля остаются редактируемыми). Привязка **необязательна** — метаданные можно ввести вручную (фильтры каталога всё равно работают).
4. Заполнить карточку: **состояние** (`new` / `used`), для Б/У — **состояние пластинки** и **состояние обложки** (грейды Mint/NM/…/Poor, у обложки ещё `Generic`), **цена**, **наличие** (кол-во ≥1), **цвет** (винила), формат, описание, **пункт отправки**, **фото**.
   - При выборе состояния «Новый» грейды пластинки (`source_quality_id`) и обложки (`cover_quality_id`) обнуляются — поля скрыты.
   - Для «Б/У» **обязательны оба грейда**: состояние пластинки (шкала Discogs, 8 значений) и состояние обложки (те же 8 + `Generic` — типовой конверт). Без них кнопка отправки заблокирована, а бэкенд отвечает 422.
5. Отправить форму. Товар создаётся в статусе **черновик** (`draft`), появляется тост «Товар создан и отправлен на модерацию», и товар индексируется в поиске. Публикация — **отдельный ручной шаг** (действие «Опубликовать» в меню карточки).

::: warning Товар всегда создаётся черновиком
Обычное создание товара всегда даёт статус `draft` — тумблера «опубликовать сразу» в форме нет. Тост «отправлен на модерацию» условен: **отдельной очереди модерации товаров нет** — допуск к продажам держится на уровне продавца (подключены ли выплаты), а публикация конкретного товара делается вручную кнопкой «Опубликовать».
:::

### Фото и видео

- Загрузка до **10** фотографий; лишние сверх лимита молча отбрасываются (и на фронте, и на бэке).
- Каждое фото — до **5 МБ**; при превышении фронт показывает тост и отменяет загрузку.
- Видео — mp4/webm/ogg/avi/mov/wmv/flv/mkv, до **~100 МБ**.
- Размерные варианты (миниатюры для списков, крупные для карточки) генерируются **асинхронно** в очереди `image-processing`.

## Флоу: продать из коллекции

Товар можно выставить прямо из **личной коллекции**: в разделе «Моя коллекция» у записи есть действие **«Продать»** — открывается та же форма товара с уже заполненными данными релиза (артист, лейбл, каталожный номер, грейды, состояние; секция ручного ввода метаданных скрыта).

При отправке создаётся товар с **наличием 1** и статусом **`draft`**. Категория подбирается по носителю (винил/CD/кассета → иначе общий «музыка»).

## Управление каталогом

Раздел **«Каталог товаров»** (`/seller/products`): вкладки **Музыка / Hi-Fi**, поиск (debounce 400мс), сортировка, «Показать по» (20/50/100), пагинация и «Показать ещё» на мобильных. Действия по каждому товару (меню карточки):

| Действие | Что делает |
|---|---|
| Редактировать | Открыть форму `/seller/products/{id}/edit` |
| Просмотреть на витрине | Открыть карточку (для не-активных — режим превью владельца) |
| Скрыть | `active → inactive` (снять с продажи) |
| Опубликовать | `inactive`/`draft → active` |
| Удалить | Удалить товар (удаление + очистка файлов) |

![Кабинет продавца → «Каталог товаров»](/screens/seller-products.png)

## Статусы товара

| Статус | Значение |
|---|---|
| Активен (`active`) | Опубликован; виден в каталоге при подключённых выплатах (допуск к продажам), наличии и ПВЗ |
| Черновик (`draft`) | Создан, но не опубликован — статус по умолчанию при создании |
| Снят с продажи (`inactive`) | Скрыт из каталога (архив) |
| Продан (`sold`) | Служебный |

Действие смены статуса из кабинета (`updateStatus`) разрешает переключать **только** `active`/`inactive`/`draft`. В служебные `sold` через кнопку статуса перевести нельзя.

## Правила и особенности

- Первый добавленный **пункт отправки** продавца автоматически подставляется в форму и привязывается к товару; ПВЗ должен принадлежать текущему продавцу (чужой отклоняется валидацией).
- **Наличие** уменьшается при заказе и возвращается при отмене/возврате; наличие синхронизируется с поиском (см. ниже).
- Привязка к Discogs необязательна — можно продавать с ручными метаданными.
- При смене названия товара **slug** пересчитывается, а старый сохраняется для 301-редиректа.
- Создание требует **наличие ≥1** — товар с нулём на складе создать нельзя.

### Синхронизация наличия с поиском

Наличие меняется **только** методами `decreaseStock()`/`increaseStock()` — они гарантируют пересчёт признака `in_stock` в поиске после коммита транзакции.

## Сценарии тестирования

**Окружение:** стенд, аккаунт продавца с подключёнными выплатами и хотя бы одним пунктом отправки. Доступы — по запросу.

### А. Добавление товара — Музыка

| # | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|
| А1 | Продавец в кабинете | «Каталог товаров» → «Добавить товар» → «Музыка» | Открылась форма; пункт отправки по умолчанию уже подставлен |
| А2 | — | Найти релиз в дискографии в форме | Артист, год, формат, лейбл, каталожный номер, страна, жанр и обложка заполнились сами; поля можно править |
| А3 | — | Не искать релиз, заполнить метаданные вручную | Товар создаётся; в каталоге находится фильтрами (жанр/формат/год) как обычный |
| А4 | — | Заполнить карточку и отправить | Тост об успехе; товар появился в списке в статусе «Черновик» |
| А5 | — | Выбрать состояние «Б/У» и не указать грейд пластинки или обложки | Кнопка отправки заблокирована, пока оба грейда не указаны |
| А6 | Выбран «Б/У» с грейдами | Переключить состояние на «Новый» | Грейды пластинки и обложки сбрасываются, поля скрываются |
| А7 | — | Указать количество 0 | Создать товар нельзя (наличие минимум 1) |
| А8 | — | Попытаться выбрать чужой пункт отправки (если доступно) | Отклоняется; сохраняется только свой ПВЗ |

| # | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|

| # | Предусловия | Шаги | Ожидаемый результат |

### Е. Управление каталогом

| # | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|
| Е1 | Есть товары обоих типов | Переключить вкладки Музыка / Hi-Fi | В каждой вкладке — только товары своего типа |

| Е3 | Товаров больше 20 | Менять «Показать по» (20/50/100), листать страницы | Размер страницы и пагинация работают; на мобильном — «Показать ещё» |

### Ж. Наличие и продажи

| # | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|
| Ж1 | Товар с наличием 1 | Покупатель оформил и оплатил заказ | Наличие 0; товар пропал из каталога |
| Ж2 | Заказ из Ж1 отменён | Проверить товар | Наличие вернулось; товар снова в каталоге |
| Ж3 | Товар с наличием N | Покупатель кладёт в корзину N+1 | Больше остатка добавить нельзя (см. [Корзина](/overview/cart-checkout)) |

| # | Предусловия | Шаги | Ожидаемый результат |
|---|---|---|---|
| З1 | Второй продавец | Открыть чужой товар в кабинете / попытаться править | Доступ запрещён |
| З2 | Обычный покупатель (не продавец) | Зайти в кабинет продавца | Уводит в личный кабинет покупателя |

## Экспорт и импорт лотов

Кнопки **Экспорт** и **Импорт** — в кабинете продавца, на странице **Мои лоты** (рядом с «Добавить лот»; на телефоне — отдельным рядом под вкладками категорий).

Рабочий цикл обновления:

1. **Экспорт** — выгружаются лоты по текущим фильтрам (вкладка категории и строка поиска). В файле есть ID каждого лота.
2. Правка в Excel — цена, наличие, статус, описание.
3. **Импорт** — тот же файл загружается обратно; изменения применяются по ID, поэтому перепутать карточки нельзя.

Строка без ID создаёт новый лот, поэтому тем же файлом можно и переносить товары с другой площадки.

::: warning Автоматической выгрузки с «Мешка» нет
Перенос с других площадок делается вручную: продавец выгружает свои лоты у них, приводит файл к нашей структуре (проще всего — по шаблону из окна импорта) и загружает. Структура файла и разбор ошибок — [Формат файла загрузки лотов](/overview/product-import-format).
:::

Ограничения: до 10 МБ и 5000 строк за раз, одновременно обрабатывается одна загрузка. Плохие строки не отменяют файл — по ним формируется отчёт с номером строки и причиной. Есть режим «только проверить, ничего не менять». Фотографии через файл не загружаются.
