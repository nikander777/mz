# Корзина и оформление

> Как из выбранных товаров получается заказ: сбор корзины, выбор позиций галочками, группировка по продавцам, доставка, получатель и переход к оплате. Технические детали — приложение [Техническая справка → Оформление заказа](/processes/checkout).

Процесс двухфазный: **корзина** (сбор товаров, выбор позиций) → **оформление** (группировка по продавцам, доставка на каждого продавца, данные получателя, создание заказов, переход к оплате).

Ключевая модель площадки: **один заказ = один продавец**. Корзина с товарами нескольких продавцов при оформлении распадается на несколько заказов, объединённых **общим платежом** (`payment_batch_id`) — покупатель платит один раз, а внутри создаётся столько заказов, сколько продавцов.

## Назначение и роли

| Роль | Что делает |
|---|---|
| **Гость** | Собирает корзину в браузере (localStorage), доходит до оформления; доставка и оплата открываются только после инлайн-регистрации |
| **Покупатель** (авторизованный) | Корзина хранится на сервере, полный цикл оформления и оплаты |
| **Продавец** | **Не может купить собственный товар** (проверки на всех уровнях). Его товары продаются, только если продавец одобрен админом |
| **Площадка** | Считает суммы, группирует по продавцам, создаёт заказы, инициирует оплату |

## Корзина

Что показано покупателю:

- Товары **сгруппированы по продавцам**; сумма и доставка считаются по каждому продавцу отдельно.
- **Выбор галочками:** по умолчанию выбраны все доступные позиции; в итог и в заказ идут только отмеченные. Есть переключатель «выбрать всё».
- **Недоступные товары** (закончились или сняты с продажи) выделяются, уходят в секцию «Больше не в наличии» и **полностью исключаются** из выбора и оформления.
- Кнопка **«Купить»** у отдельной позиции переводит в оформление только с этим товаром (остальные снимаются с выбора).
- **Гостевая корзина** хранится в браузере и **переносится** в аккаунт при входе/регистрации.

![Корзина: группировка по продавцам, галочки выбора, итог](/screens/buyer-cart.png)

### Как работает выбор галочками

Технически хранятся **снятые** позиции (а не выбранные). Поэтому:

- новый добавленный товар автоматически оказывается выбранным;
- недоступные товары в выборе не участвуют вообще;
- «выбрать всё» и итоговые суммы считаются только по доступным позициям;
- после успешной оплаты из корзины удаляются **только оплаченные** (выбранные) позиции, остальные остаются.

## Оформление

Страница оформления доступна и гостю, и авторизованному. Порядок:

1. **Проверка выбора.** Если в корзине нет ни одной выбранной позиции — происходит возврат в корзину (`/cart`).
2. **Данные получателя** — имя (от 2 символов), телефон (от 10 цифр), **email обязателен**. У авторизованного поля предзаполняются из профиля.
3. **Доставка** — способ (ПВЗ или курьер) и пункт выдачи/адрес **по каждому продавцу** отдельно; стоимость и срок рассчитываются на сервере.
4. **Способ оплаты** — карта / СБП / сохранённая карта.
5. **Для гостя** вместо блока оплаты показывается **инлайн-регистрация**: после неё гостевая корзина сливается с аккаунтом, данные пересобираются, и (если после слияния остались выбранные товары) открывается оплата.
6. Кнопка перехода к оплате активна, когда: пользователь авторизован, есть продавцы, **у всех** продавцов выбрана доставка, заполнен получатель и выбран способ оплаты.

По нажатию создаётся **по одному заказу на продавца** (объединены общим `payment_batch_id`), списывается остаток товара, и открывается оплата → [Оплата](/overview/payment).

![Оформление: получатель, доставка по продавцам, способ оплаты](/screens/buyer-checkout.png)

::: warning На согласование. Корзина не очищается сразу
Заказы создаются (и остаток товара списывается) **в момент нажатия «Оплатить»**, до фактической оплаты. Корзина очищается **только после подтверждения оплаты**. Если оплату отменить — заказы остаются в статусе «Ожидает оплаты», товар числится списанным, а корзина остаётся заполненной.
:::

## Стоимость заказа

Сервер по каждому заказу считает:

```
Итог заказа = стоимость товаров + доставка
```

**Комиссия площадки** 

Комиссия сервиса МОНЕТА зависит от суммы товаров:

| Сумма товаров | Комиссия |
|---|---|
| ≤ 300 ₽ | 3 % от суммы |
| > 300 ₽ | 9 ₽ + 2 % от суммы свыше 300 ₽ |

Примеры: 300 ₽ → 9 ₽; 301 ₽ → 9,02 ₽; 1000 ₽ → 23 ₽.

Также исходя из документации за фискализацию будет добавлено 0.5% комиссии. 

::: warning На согласование
Какой размер комиссии будет установлен. Важно информировать продацов и возможно выводить блок "Вы получите за заказ N руб." при создании товара (блок установки стоимости товара). 
:::


## Слияние гостевой корзины

При входе/регистрации гостевая корзина переносится в аккаунт:

- перенос идёт **в обход обычных ограничений** (гость мог собрать корзину до подтверждения телефона);
- **пропускаются** товары: удалённые, снятые с продажи, **собственные** товары покупателя, распроданные (остаток 0);
- при совпадении с уже имеющейся позицией количество суммируется, но обрезается: `не больше min(остаток на складе, 100)`;
- операция идемпотентна (повторный вызов не задваивает), выполняется одним защищённым потоком без гонок.

## Уведомления

После успешного создания заказов рассылаются уведомления (каналы — email / Telegram / Max, по настройкам получателя):

| Событие | Кому | Что |
|---|---|---|
| Заказ создан | Продавцу | Уведомление о новом заказе по его товарам |
| Заказ создан | Покупателю | Подтверждение оформления заказа |

Сбой отправки уведомления **не откатывает** заказ — заказ уже создан, ошибка пишется в лог.

## Все сценарии и крайние случаи

| Сценарий | Поведение |
|---|---|
| Добавление собственного товара | Отклоняется (нельзя купить свой товар) |
| Телефон не подтверждён + добавление в корзину | Отклоняется, просьба подтвердить телефон |
| Добавление сверх остатка | Ошибка «Доступно: N» |
| Товар кончился/снят после добавления | В корзине помечен недоступным, уходит в «Больше не в наличии», исключён из выбора и заказа |
| Пустой выбор на оформлении | Возврат в корзину |
| Корзина нескольких продавцов | Несколько заказов, один общий платёж, доставка на каждого продавца |
| Гость на оформлении | Инлайн-регистрация → слияние корзины → пересбор; если выбранных не осталось — возврат в корзину |
| Слияние: свой/удалённый/распроданный товар | Пропускается, не переносится |
| Слияние: превышение остатка/лимита | Обрезка до `min(имеющееся + гостевое, остаток, 100)` |
| Кнопка «Купить» из корзины | Оформление только с этим товаром |
| Отмена оплаты после создания заказов | Заказы «Ожидают оплаты», остаток уже списан, корзина не очищена; товар вернётся в наличие только при отмене заказа |
| Успех оплаты, выбрана часть корзины | Удаляются только оплаченные позиции, остальные остаются |
| Успех оплаты, выбрана вся корзина | Корзина очищается целиком |
| Гость: товар из корзины больше не существует | Позиция вычищается из браузера при загрузке |

## Статусы созданного заказа

Заказ создаётся в статусе **«Ожидает оплаты»** (`PENDING`), с оплатой `pending` и доставкой `pending`. Каждому заказу присваивается автономер, пишется первая запись истории статусов «Заказ создан через checkout». Дальнейший жизненный цикл — см. [Жизненный цикл заказа](/overview/order-lifecycle) и [Оплата](/overview/payment).

## Правила и особенности

- Один заказ = один продавец; заказы одной покупки оплачиваются вместе одним `payment_batch_id`.
- В итог и в заказ идут только выбранные (отмеченные) товары.
- Пустой выбор → переход к оплате заблокирован (возврат в корзину).
- Товар, закончившийся между добавлением и оформлением, попадает в «Больше не в наличии» и исключается.
- Данные получателя (`customer_name/phone/email`) — все обязательны, email в том числе.
- Каждый заказ хранит **снапшот товара** (название, описание, цена на момент заказа) — на случай последующих изменений в каталоге.
- Остаток товара списывается атомарно и **синхронизируется с поисковым индексом** (Meili) вручную, иначе индекс разошёлся бы с БД.
- Вес посылки для расчёта доставки считается как **500 г × количество** (фиксированная оценка).

## Техническая часть

Корзина (API добавления/изменения, слияние гостевой), предварительный расчёт, создание заказов по продавцам, расчёт доставки, формирование адреса и отправления, комиссия площадки, синхронизация остатка с поиском, уведомления и полный разбор рисков — приложение [Техническая справка → Оформление заказа](/processes/checkout).
