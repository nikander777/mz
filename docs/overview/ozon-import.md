# Перенос товаров с Ozon

> Продавец переносит свои пластинки, CD и кассеты с Ozon по ключу Seller API. Файл не нужен. Лоты создаются черновиками с фото, ценами, остатками и характеристиками. Повторный перенос обновляет уже перенесённое.

## Зачем

Многие продавцы винила уже торгуют на Ozon, и заводить сотни карточек заново для них — главный барьер. Выгрузку из Ozon через XLS-шаблоны пришлось бы разбирать отдельно под каждую категорию, а Ozon регулярно меняет эти шаблоны. Seller API отдаёт те же данные стабильно, а ключ только на чтение безопасен для продавца.

## Как запускает продавец

1. В кабинете Ozon: «Настройки» → «Seller API» → «Сгенерировать ключ». Указать, что ключ для внешнего сервиса Muzilla, выбрать роль **Product read-only** (или Admin read only).
2. В Muzilla: «Мои лоты» → плашка **Перенести с Ozon** (её можно скрыть) или окно **Импорт** → «перенести напрямую по ключу API».
3. Ввести Client-Id и Api-Key → **Проверить ключ**. Muzilla показывает число товаров, срок действия ключа и предупреждает, если у ключа есть права на изменение.
4. Подтвердить права на фото и описания. Решить, пропускать ли товары без остатка на своём складе (по умолчанию пропускаем) → **Перенести**.
5. Перенос идёт в фоне, окно можно закрыть. По окончании показываются счётчики и ссылка на отчёт «что не перенеслось и почему» (по артикулам Ozon).

## Что и как переносится

| Ozon | Muzilla |
|---|---|
| Артикул (`offer_id`) | `source = ozon`, `source_id` — ключ повторного переноса |
| Название | Название (обрезается до 200 символов) |
| Аннотация (атрибут 4191, HTML) | Описание простым текстом |
| Цена (`price`, только RUB) | Цена |
| Остаток FBS + rFBS (наличие минус резерв) | Наличие. FBO не учитывается: товар лежит на складе Ozon |
| «Тип носителя» или название | Формат: Vinyl / CD / Cassette, подраздел выводится сам |
| «Виниловая пластинка Б/У», «Состояние» | Состояние «Б/У» |
| «Сохранность винила / конверта» (Goldmine) | Грейды носителя и обложки. EX → VG+, Still Sealed → новая |
| Исполнитель, Издатель, Год издания, Каталожный номер | Артист, лейбл, год, каталожный номер |
| Жанр музыки | Жанр Discogs верхнего уровня; неизвестный жанр не пишется («Классический рок» — Rock) |
| Страна-изготовитель | Название страны как в Discogs (`Europe`, `US`, `Germany`); фронт переводит обратно |
| Штрихкод (EAN/UPC, без `OZN…`) | `release_barcode` |
| Вес | Вес в граммах |
| Фото (главное первым, до 10) | Скачиваются в фоне, только для лотов без своих фото |

Характеристики Ozon приходят числовыми ID, и у разных типов товаров ID свои. Поэтому сопоставление идёт по **названию** характеристики из справочника типа (`/v1/description-category/attribute`) через списки синонимов (`OzonProductMapper::FIELDS`). Если Ozon переименует характеристику, достаточно добавить синоним.

**Не переносятся:**
- архивные товары;
- техника и аксессуары (проигрыватели, конверты, щётки — определяется по названию, если нет «Типа носителя»);
- товары без цены в рублях;
- Б/У без грейдов — действует то же правило, что и в форме и в файле;
- по выбору продавца — товары без остатка на своём складе. Такие считаются пропущенными, но в отчёт об ошибках не попадают.

Лоты создаются **черновиками**, ПВЗ подставляется по умолчанию. У существующего лота (найден по `source` + `source_id`) обновляются только пришедшие поля, статус не меняется.

Сразу после переноса запускается «[Заполнить дискографию](./release-link)» по перенесённым лотам без привязки: продавец видит баннер запуска на «Моих лотах», проверяет найденное и применяет. Подбор берёт не только текст лота, но и его поля «Артист», «Штрихкод», «Каталожный номер», а альбом вычленяет из заголовка после артиста («Camel - Dust and Dreams (виниловая пластинка LP…)» → «Dust and Dreams»): заголовки маркетплейсов шаблону «Артист – Альбом» не следуют. Если у продавца уже есть незавершённый запуск, новый не стартует — причина видна в итоге переноса.

**Статистика переноса** — `product_imports.options.ozon_stats`: сколько товаров пришло с настоящим EAN, только со служебным штрихкодом Ozon и без штрихкода, и какие характеристики (по названию) у товаров заполнены. По ней дописываются синонимы `OzonProductMapper::FIELDS` без ключа продавца.

## Ключ продавца

- Запросы к Ozon идут только с бэка: Ozon принимает их только от сервера.
- Ключ хранится в `product_imports.credentials` (`encrypted:array`, AES по `APP_KEY`), скрыт из API и **стирается сразу по завершении или падении** переноса.
- Ключ Ozon действует 3 месяца. Для разового переноса этого достаточно, постоянной синхронизации пока нет.

## Устройство

Перенос — та же запись `ProductImport` с `source = ozon`, тот же список, поллинг и отчёт об ошибках, что у загрузки файлом.

```
OzonImportController ─ check  → OzonImportService::check   (/v3/product/list limit 1 + /v1/roles)
                     └ store  → OzonImportService::createImport → ProcessProductImport (очередь imports)
ProcessProductImport ─ source=ozon → OzonProductImporter
   /v3/product/list (все страницы, без архива)
   пачками по 100: /v4/product/info/attributes + /v3/product/info/list
                   + /v1/description-category/attribute (раз на тип товара)
   OzonProductMapper → строка формата ProductSheetSchema
   ProductImportService::applyRows → ProductImportRowProcessor (общие правила, upsert по source_id)
   штрихкод → release_barcode; фото → ImportOzonProductPhotos (очередь imports)
```

**Фото.** Задача качает только с хостов из `services.ozon.image_hosts` (CDN Ozon), по https, без редиректов, до 10 МБ, `Content-Type: image/*`. Без белого списка это был бы запрос на любой адрес из ответа API, включая внутреннюю сеть. Лот с уже заполненным `photo_0` не трогается, поэтому повтор задачи безопасен.

**Лимиты.** Ozon допускает 50 запросов в секунду на Client-Id. Перенос делает 2 запроса на сотню товаров, на `429` клиент ждёт `Retry-After` (до 3 повторов). За один перенос — до 10 000 товаров.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/profile/products-io/ozon/check` | Проверка ключа: число товаров, срок, права на запись |
| `POST` | `/api/profile/products-io/ozon/imports` | Запуск переноса (`client_id`, `api_key`, `skip_without_stock`, `rights_confirmed`) |

Конфиг: `OZON_SELLER_API_URL` (по умолчанию `https://api-seller.ozon.ru`), `OZON_SELLER_API_TIMEOUT`.

## Не проверено на живых данных

Номера характеристик и их точные названия для типов «Виниловая пластинка», «Музыкальный CD», «Аудиокассета» взяты по документации и публичным карточкам, а не из ответа API реального продавца. Первый перенос у реального продавца нужно разобрать по отчёту об ошибках и при необходимости дополнить синонимы.
