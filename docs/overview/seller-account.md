# Кабинет продавца

> Карта рабочего места продавца: товары, заказы, финансы и выплаты, статистика, доставка, отзыв­чивость магазина. Отдельные процессы вынесены на свои страницы (ссылки в таблице разделов). Техническая часть — в конце страницы.

## Назначение и роли

Единое рабочее место продавца. Из него ведётся весь жизненный цикл магазина: витрина, каталог лотов, входящие заказы, подключение выплат, статистика продаж и возвратов, точки отправки, отзывы и чёрный список.

| Актор | Что делает в кабинете |
|---|---|
| **Продавец** (`is_seller=true`) | Редактирует витрину магазина, ведёт каталог лотов, подтверждает/отклоняет заказы, проходит онбординг выплат, настраивает точки отправки |
| **НКО МОНЕТА** | Вне системы: проверяет анкету выплат и «Заявление о присоединении», активирует приём денег и допуск к продажам |

### Переключатель «Покупатель / Продавец»

Вверху меню — переключение контекста между покупательским (`/profile`) и продавецким (`/seller`) кабинетом. Это **чисто навигация**, никакого серверного «режима» нет — роль определяется маршрутом.

- **Десктоп:** вкладка «Покупатель» — ссылка на `/profile`, «Продавец» — активная вкладка.
- **Мобайл:** переключатель виден только при `is_seller`; текущий контекст вычисляется по `route.path.startsWith('/seller')`.

Единый источник структуры меню — `sellerNav` в `useProfileNav.ts`. Из него рендерятся и десктоп-сайдбар, и мобильное меню, поэтому они не расходятся.

## Допуск к продажам

Продавец регистрируется (ЮЛ/ИП), затем **подключает выплаты** — заполняет анкету в кабинете и заключает договор («Заявление о присоединении») с НКО МОНЕТА. После подключения выплат продавец **допущен к продажам**: его лоты публикуются в каталоге и по ним можно оформлять заказы. Ручного одобрения или модерации продавца администратором нет — допуск открывается сразу после заключения договора с НКО.

Только ЮЛ/ИП. ФЛ и самозанятые как продавцы запрещены (соответствующие эндпоинты сняты). Подробнее — в разделе [Подключение выплат](#подключение-выплат-seller-payout-setup) ниже и на странице [Выплаты](/overview/payouts).

**Товар виден в публичном каталоге, когда одновременно:** он опубликован (active), есть в наличии, у него указан пункт отправки (ПВЗ) **и** продавец допущен к продажам (выплаты подключены). Если хотя бы одно условие не выполнено — товар в каталог не попадает.

### Пока выплаты не подключены

Продавец без подключённых выплат может создавать и вести товары, но ещё не допущен к продажам:

- лоты продавца **скрыты** из публичного каталога;
- карточка товара по прямой ссылке отдаёт **404**;
- при попытке купить такой товар checkout отклоняет заказ: у продавца не подключены выплаты;
- в каталоге кабинета — жёлтая плашка «Пока выплаты не подключены, товары не публикуются в каталоге».

**Важно:** это ограничивает только публикацию/видимость. **Создавать и редактировать лоты можно** и до подключения выплат — они просто не видны покупателям.

## Разделы подробно

### Профиль продавца — `/seller`

Корневая страница кабинета. Редактирование витринных данных магазина, статус подключения выплат, read-only реквизиты, удаление профиля.

**Баннеры допуска к продажам:**

- выплаты ещё не подключены → жёлтый баннер «Подключите выплаты, чтобы начать продавать» (товары скрыты из каталога);
- выплаты подключены → зелёная плашка «Допуск к продажам открыт» в шапке.

**Блоки:**

| Блок | Поля | Режим |
|---|---|---|
| Магазин | Название магазина (видно покупателям), адрес страницы (`/u/{slug}`) | Редактируется |
| Данные о продавце | Тип: Физлицо / ИП / ЮЛ | Только чтение (меняется в «Подключении выплат») |
| Данные о компании (ЮЛ/ИП) | Название, форма, ИНН, ОГРН/ОГРНИП, КПП (ЮЛ), юр. адрес | Только чтение (зеркало анкеты) |
| Информация о продавце | Описание магазина | Редактируется |
| Контакты | Контактные данные | Редактируется |
| Настройки продавца | Оплата доставки, стандартное описание, автосообщение | Редактируется |
| Удалить профиль | Причина удаления + подтверждение | — |

Кнопка «Сохранить» в блоке появляется только при реальных изменениях. Адрес страницы (`slug`) нормализуется автоматически (транслит + уникальность); если оставить пустым — генерируется из названия магазина. Частичное сохранение не затирает незаданные поля.

**Удаление профиля:** в транзакции удаляется файл регистрационного документа, профиль помечается удалённым (soft-delete), `is_seller` сбрасывается в `false`, действие логируется. После — переход в покупательский `/profile`.

### Каталог товаров — `/seller/products`

CRUD лотов с двумя вкладками — **Музыка** и **Hi-Fi аппаратура**, поиском, сортировкой, выбором количества на странице и пагинацией. Кнопка «Добавить товар».

- Пока выплаты не подключены — жёлтая гейт-плашка; создание лотов **не блокируется**.
- При создании товара точка отправки автозаполняется дефолтным ОПС Почты продавца. Чужой `pickup_point_id` → ошибка 422.
- Лот без точки отправки **не попадает в публичный каталог**.

Подробно — [Работа с товарами](/overview/seller-products).

### Заказы (лоты) — `/seller/orders`

Список заказов, где текущий пользователь — продавец. Вкладки **Активные** / **Завершённые**, поиск по номеру/имени (серверный, с задержкой ввода 400 мс), фильтр периода, пагинация.

Разбиение по статусам (клиентское):

- **Активные:** `PENDING, CONFIRMED, PAID, PROCESSING, SHIPPED`.
- **Завершённые:** `COMPLETED, DELIVERED, CANCELLED, REFUNDED`.

Действия по заказу — подтверждение и отклонение в течение 48 ч. Бейдж «Заказы (лоты)» в меню = число заказов в статусах `PENDING` + `PAID`. Полный жизненный цикл — [Заказы](/overview/orders).

### Статистика — `/seller/statistics`

Агрегаты **Продажи** и **Возврат** по категориям товара за период, с диаграммами.

**Период:** день / неделя / месяц / квартал / год / всё время; по умолчанию — месяц.

- **Продажи** считаются по статусам `PAID, DELIVERED, COMPLETED`.
- **Возвраты** — по `CANCELLED, REFUNDED`, причём возврат учитывается, только если заказ в статусе `REFUNDED` **или** по нему есть успешная запись возврата.
- Проценты: доля продаж = продажи / (продажи + |возвраты|) × 100.
- Диапазоны периодов **скользящие**: «месяц» = «за последний месяц от сегодня», а не «календарный месяц». То же для квартала и года. «Всё время» — с 2000-01-01.

### Финансы — `/seller/finances`

Отдельной страницы у продавца нет — раздел ведёт (301-редирект) на покупательские [Финансы](/profile/finances) с историей операций. Логика выплат описана на странице [Выплаты](/overview/payouts).

### Подключение выплат — `/seller/payout-setup`

Онбординг продавца (**только ЮЛ/ИП**) в НКО МОНЕТА: анкета → отправка → подписание «Заявления о присоединении» → активация.

**Статусы онбординга:** `not_started` → `filling` → `agreement_required` → `verifying` → `active`; при просрочке договора — `blocked`.

**Экраны по статусу:**

- `active` → зелёный баннер «Выплаты подключены»;
- `verifying` → синий баннер «Проверка НКО МОНЕТА» + блок подписания договора: скачать персональное заявление, скачать общий шаблон оферты, загрузить подписанную копию (PDF ≤ 10 МБ), кнопка «Обновить статус»;
- прочие статусы → форма анкеты.

**Форма** состоит из 5 блоков: организация (ИНН + автозагрузка из ЕГРЮЛ, название), контакты и реквизиты (email, телефоны, ФИО, адреса, обороты, орган регистрации, для ЮЛ — уставный капитал; согласия), руководитель / ИП, паспорт, банк (расчётный счёт 20 цифр, БИК 9). ИНН можно «подгрузить из ЕГРЮЛ» — название и адреса подставятся автоматически.

**После отправки анкеты** форма становится **только для чтения** (баннер «Заявка отправлена — статус…»), правки — только через `support@muzilla.ru`. Юридическую форму после отправки менять нельзя.

**Дедлайн:** «Заявление о присоединении» должно поступить в НКО в течение **30 дней**, иначе приём платежей блокируется. Полный флоу — [Выплаты продавцам](/business/seller-payouts-flow).

### Доставка — `/seller/delivery`

Справочная информационная страница по каналам доставки продавца с инструкцией. Состояния и API у неё нет.

### Пункты отправки — `/seller/pickup-points`

Точки, **откуда продавец отправляет** заказы: ОПС Почты России и ПВЗ СДЭК (через карту). Не путать с адресами покупателя.

Три блока: список точек (радио «основной», бейджи перевозчика, удаление); форма добавления ОПС Почты (автокомплит по индексу/названию); кнопка «Добавить пункт отправки СДЭК» → выбор ПВЗ на карте.

**Логика первой точки Почты:** первый добавленный ОПС Почты **массово привязывается ко всем лотам** продавца → тост «Привязано к N лотам». ПВЗ СДЭК к товарам **не привязывается**.

**Дефолты независимы по перевозчику:** первый ОПС Почты и первый ПВЗ СДЭК оба становятся основными в своей группе.

**Удаление точки:**

- если удаляется основная и есть замена того же перевозчика — замена становится основной, лоты перепривязываются на неё;
- если точка **единственная** — лоты получают пустую точку отправки и **исчезают из публичного каталога**.

### Чёрный список — `/seller/blacklist`

301-редирект на покупательский [ЧС](/profile/blacklist): список заблокированных пользователей и разблокировка. **Добавление в ЧС происходит не здесь**, а на публичной странице продавца `/u/{id}`. Нельзя заблокировать себя или повторно уже заблокированного.

### Отзывы — `/seller/reviews`

Показ отзывов покупателей о самом магазине, только просмотр (действия отключены). Отзывы создаются покупателями только из завершённого заказа. Подробно — [Отзывы](/overview/reviews).

## Уведомления

| Событие | Канал | Что показывается |
|---|---|---|
| Есть неподтверждённые заказы | In-app | Красный бейдж с числом на «Заказы (лоты)» |
| Анкета выплат требует внимания | In-app | Красный «!» на «Подключение выплат» |
| Выплаты не подключены | In-app | Баннер на `/seller` |
| Нет ОПС Почты | In-app | Глобальный баннер «требуется пункт отправки» |
| Продавец не допущен к продажам | In-app | Гейт-плашка в каталоге |
| Сохранение, добавление/удаление ПВЗ, «Привязано к N лотам» | Toast | Всплывающее подтверждение |
| Неподтверждённые заказы (3/6/24/36 ч), напоминания по ПВЗ | Email / Telegram / MAX | Вне страниц кабинета |

## Все сценарии и крайние случаи

| Ситуация | Что происходит |
|---|---|
| Продавец без подключённых выплат создаёт лоты | Лоты создаются, но скрыты из каталога; карточка по ссылке → 404 |
| Покупка товара продавца без подключённых выплат | Checkout отклоняет заказ: у продавца не подключены выплаты |
| Продавец без профиля («ноунейм») | Продавать нельзя, пока не создан профиль и не подключены выплаты |
| Удаление профиля продавца | Soft-delete профиля, `is_seller=false`, файл рег. документа удаляется физически; переход в `/profile` |
| Удаление единственной точки отправки | Лоты теряют точку отправки → исчезают из публичного каталога |
| Первый ОПС Почты | Массовая привязка ко всем лотам продавца (тост «Привязано к N лотам») |
| Анкета выплат отправлена | Форма read-only, правки только через поддержку; юр. форму менять нельзя |
| «Заявление о присоединении» не поступило за 30 дней | Приём платежей блокируется (`blocked`) |
| Смена формы ЮЛ → ИП в анкете | Уставный капитал обнуляется, документ полномочий = «иное», ИНН руководителя = ИНН ИП |

## Статусы

**Допуск к продажам** (зависит от подключения выплат):

| Состояние | Каталог | Витрина |
|---|---|---|
| Выплаты не подключены | Лоты скрыты | Жёлтый баннер «подключите выплаты» |

## Правила и особенности

- Все страницы `/seller/*` требуют авторизации и подтверждённого телефона; не-продавец перенаправляется в `/profile`.
- Название магазина, описание, контакты и настройки редактируются на `/seller`; тип продавца и реквизиты компании — только через «Подключение выплат» или поддержку.
- Допуск к продажам открывается подключением выплат: пока договор с НКО МОНЕТА не заключён, лоты не публикуются и заказ по ним оформить нельзя.
- Пункты Коллекция, Избранное, Настройки, а фактически и Финансы и Чёрный список ведут в покупательский кабинет.
