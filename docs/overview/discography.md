# Дискография

> Раздел «Дискография» — большой музыкальный справочник на базе внешней базы **Discogs** (артисты, релизы, мастер-релизы, лейблы). Это **не товары на продажу**, а каталог записей, к которым привязываются товары маркетплейса. Технические детали (endpoint'ы, драйверы каталога Meili/БД, фасеты, поведение сортировок, команды импорта и индексации) — внизу, в [Технической документации](/processes/catalog-search).

## Что это

Дискография — музыкальный каталог из дампов Discogs.com. Четыре сущности:

- **Релизы (releases)** — конкретное издание (винил/CD/кассета конкретного года, страны, лейбла).
- **Мастера (masters)** — «обобщённая» запись альбома, объединяющая все его издания-версии.
- **Артисты (artists)** — исполнители, с группами и псевдонимами.
- **Лейблы (labels)** — звукозаписывающие компании, с родительскими лейблами.

Живёт в отдельном сервисе (`discogs/`); интерфейс — в разделе `/disco`. Сами товары и продажа — в основном сервисе (`main/`); дискография связана с продажами только через счётчик «N продавцов» (`marketplace_count`), который подмешивается из каталога товаров.

## Назначение и роли

| Актор | Что может | Где |
|---|---|---|
| Гость | Листать все списки и карточки, фильтровать, сортировать, искать, добавлять в избранное (хранится в браузере) | Публично |
| Авторизованный пользователь | Всё то же + избранное через аккаунт + добавление релизов в свою коллекцию (с карточки релиза) + кнопка «Добавить релиз/мастер-релиз» в шапке (ведёт в `/profile/discogs-import`) | Публично + ЛК |
| Администратор | Импорт дампов, реиндексация, настройка драйверов каталога — по SSH командами | Сервер |

Чтение каталога **публично**. Все внутренние API дискографии защищены токеном сервиса: браузер напрямую в `discogs/` не ходит — только через серверные прокси Nuxt, которые добавляют токен. Кнопка «Добавить релиз» в шапке видна **только авторизованным**.

## Как наполняется

Наполнение **ручное, примерно раз в месяц** — по факту выхода очередного дампа Discogs (публикуются ежемесячно). Автоматического расписания импорта нет; администратор запускает его вручную по SSH.

Порядок:

1. Большой XML-дамп (~57 ГБ распакованный) разбивается на части и импортируется в несколько потоков командой импорта. Сначала грузятся **тексты** (данные о релизах, артистах, лейблах, связях) — это ~7–10 часов на ~19 млн релизов.
2. **Картинки при массовом импорте не загружаются** (режим «только миниатюры» по умолчанию, полные — лениво). Сразу после импорта часть карточек без обложек — это нормально.
3. Массовый импорт идёт в обход событий моделей, поэтому поисковый индекс **не наполняется автоматически** — после импорта администратор запускает отдельную реиндексацию. Без неё листинги на поисковом драйвере окажутся почти пустыми (наполнены ~на 3%).

Продавец может добавить в каталог **отдельный недостающий релиз** сам — через «Добавить релиз в дискографию»: система находит запись в Discogs и подтягивает её (точечный импорт релиза/артиста/лейбла/мастера, есть и батч-импорт).

### Обложки — как появляются

- В **списках** показывается лёгкая каталожная миниатюра (200×200 WebP). Карточки с реальной миниатюрой всегда идут первыми, без обложки — в конце (сортировка всегда начинается с признака «есть миниатюра»).
- **Оригиналы и крупные размеры догружаются в фоне при первом заходе на карточку.** Открыли релиз без миниатюры — система ставит фоновую задачу в приоритетную очередь загрузки картинок и качает обложку; если миниатюра есть, но нет полноразмерных — ставит задачу догрузки полных изображений (medium/large/оригинал). Плюс есть фоновый «дозагрузчик», который добирает обложки массово.
- Поэтому нормально, что у только что импортированного каталога часть карточек сначала без картинок — это не ошибка, а ленивая загрузка.

## Страницы

Четыре типа, у каждого — **список** и **детальная карточка**:

| Тип | Список | Карточка |
|---|---|---|
| Релизы | `/disco/releases` | `/disco/release/{id}` |
| Артисты | `/disco/artists` | `/disco/artist/{id}` |
| Мастера | `/disco/masters` | `/disco/master/{id}` |
| Лейблы | `/disco/labels` | `/disco/label/{id}` |

Списки переключаются табами (Релизы / Артисты / Мастера / Лейблы), вид — **сетка или список**, можно менять размер страницы; постраничная навигация + кнопка «Показать ещё».

## Пошаговый флоу

### A. Открытие списка (например, `/disco/releases`)

1. Страница читает параметры из адреса (поиск, жанры, стили, страны, годы, форматы, лейблы, сортировка, страница, размер страницы, вид) и подставляет их в фильтры.
2. Параллельно грузятся **фасеты** (варианты фильтров со счётчиками) и **сам список**.
3. Запрос уходит через серверный прокси Nuxt в сервис `discogs/`. Там выбирается драйвер каталога (поисковый Meili или база данных) — форма ответа для фронта **одинаковая**, разницы пользователь не видит.
4. Список возвращается вместе с итогами: сколько всего найдено, размер и номер страницы, число страниц.
5. Фронт показывает карточки (`ReleaseCard` в коротком/длинном варианте под сетку/список). Пагинация: номера страниц + «Показать ещё» + предыдущая/следующая.
6. Смена фильтра, сортировки, размера или страницы сбрасывает список на первую страницу, очищает накопитель и обновляет адрес (дефолтные значения в адрес не пишутся). Кнопка **«Показать ещё» дописывает** следующую страницу к уже показанным и **адрес не меняет**.

### B. Карточка релиза

1. При каждом открытии карточки счётчик просмотров релиза увеличивается на 1 (на этом строится «популярность»).
2. Подгружаются все связи: артист(ы), лейбл, мастер, треклист, штрих-коды и каталожные номера, компании, видео, серии, изображения.
3. Лениво докачиваются картинки (см. «Обложки»).
4. Возвращаются доступные URL изображений: каталожная миниатюра всегда, а medium/large/оригинал — только когда полные картинки уже скачаны.

Карточки артиста и лейбла работают так же (докачка по своему типу). У мастера ленивая загрузка идёт по его главному релизу.

### C. Связи: версии, похожие, дискография

- **Версии** (на релизе/мастере): если у релиза нет мастера — версий нет; иначе показываются другие релизы того же мастера.
- **Похожие релизы**: если мастер есть — другие версии этого мастера (свежие сверху); если мастера нет — релизы главного артиста; если и главного артиста нет — пусто.
- **Дискография артиста**: релизы группируются по мастерам (у каждого — счётчик версий), одиночные релизы идут отдельно; сбоку статистика по типам (альбомы / синглы / сборники / видео / прочее, определяется по описанию формата) и свои фильтры (тип / формат / страна / год / лейбл / поиск).
- **Лейбл**: карточка показывает родительский лейбл и релизы лейбла.

## Сортировки

Разные для каждого типа (подписи — как в интерфейсе):

| Тип | Сортировки | По умолчанию |
|---|---|---|
| Релизы | По популярности · По названию · По году · По исполнителю | По популярности |
| Артисты | По алфавиту · По популярности (по числу релизов) | По алфавиту |
| Мастера | По популярности · По названию · По году · По исполнителю | По популярности |
| Лейблы | По названию · По популярности | По названию |

«Популярность» релизов и мастеров считается по числу открытий карточки; артистов и лейблов — по числу релизов. **Любая** сортировка начинается с признака «есть миниатюра» (карточки с обложкой — первыми).

## Фильтры

У каждого пункта фильтра — счётчик (сколько записей подходит). Превью первых нескольких значений, «Показать ещё»/«Скрыть», у лейблов — свой поиск по названию с прокруткой:

| Тип | Фильтры |
|---|---|
| Релизы | Жанры · Стили · Страна · Год · Формат · Лейбл |
| Артисты | Первая буква (лат./кир.) · Жанры · Стили · Страна · Год |
| Мастера | Жанры · Стили · Страна · Год |
| Лейблы | Первая буква (лат./кир.) |

Внутри категории — ИЛИ (можно выбрать несколько значений), между категориями — И. Активные фильтры показываются тегами сверху с крестиком сброса на каждую категорию; для лейбла тег показывает его название.

## Избранное

Сердечко доступно и гостю (хранится в браузере, при входе переносится в аккаунт), и авторизованному. Все типы попадают в общий раздел «Избранное» личного кабинета. Клик по сердечку в карточке списка не открывает саму запись (переход по ссылке подавлен).

| Тип | Из списка | С карточки |
|---|---|---|
| Релиз | ✅ | ✅ |
| Артист | ✅ | ✅ |
| Мастер | ✅ | ✅ |
| Лейбл | ❌ | ✅ (только с карточки лейбла) |

## Коллекция

Свою музыкальную коллекцию пользователь пополняет прямо из дискографии — с **карточки релиза**.

### Как добавить

1. На карточке релиза (`/disco/release/{id}`) под кнопкой «Купить релиз» есть кнопка **«Добавить в коллекцию»**. Если релиз уже есть в коллекции, под кнопкой показан счётчик **«В коллекции: N шт»**.
2. Клик открывает окно добавления: сверху — карточка релиза (обложка, название, артист, год, формат — уже заполнены), ниже — данные экземпляра:
   - **Состояние**: «Новый, запакованный» (по умолчанию) или «Б/У». Для Б/У обязательно указать **состояние пластинки** (грейд Mint…Poor) — без него добавить нельзя.
   - Опционально: состояние обложки и упаковки, **цвет пластинки** (чёрный / цветной / спецэффекты), цена покупки, примечание.
   - **Количество** — от 1 до 999.
3. «Добавить» → зелёный тост «Релиз добавлен в коллекцию», счётчик на карточке релиза увеличивается.

Один и тот же релиз можно добавлять **несколько раз** — каждая запись это отдельный «вариант» (например, разные издания или экземпляры в разном состоянии); счётчик «В коллекции» суммирует все варианты.

### Гость

С карточки релиза добавление попросит **войти** (откроется окно авторизации; после входа окно добавления откроется само). При этом раздел «Моя коллекция» доступен и гостю: там релиз добавляется через поиск по дискографии, записи хранятся в браузере и при входе автоматически переносятся в аккаунт.

### Что дальше

Коллекция живёт в личном кабинете — **«Моя коллекция»** (`/profile/collection`): поиск по своим записям, редактирование, изменение количества, скрытие отдельных позиций (или всей коллекции) из публичного профиля, удаление, добавление релиза в избранное, переход к продавцам этого релиза в каталоге и действие **«Продать»** — выставить экземпляр из коллекции на витрину (открывается форма товара с уже заполненными данными релиза). Также доступен **импорт коллекции из Discogs** (CSV-файл). Подробнее — [Личный кабинет покупателя](/overview/buyer-account).

## Связь с продажами (marketplace_count)

На карточках/в блоках дискографии есть счётчик «N продавцов» — сколько продавцов маркетплейса выставили товар на этот релиз.

## Уведомления

В самом разделе дискографии клиентских уведомлений нет. Косвенно:

| Событие | Что показывается |
|---|---|
| «Поделиться релизом» (кнопка на карточке) | Тост «Ссылка скопирована» / «Ошибка копирования» |
| Релиз в избранном появился в продаже | Уведомление приходит из основного сервиса (за пределами дискографии) |

## Все сценарии и крайние случаи

| Ситуация | Что происходит |
|---|---|
| Фильтр без совпадений | Пустое состояние «… не найдены» + кнопка «Сбросить все фильтры» |
| Размер страницы больше 200 | Ограничивается 200 |
| Переход на несуществующую страницу (0 или больше числа страниц) | Ничего не делает (no-op) |
| Глубокая пагинация на поисковом драйвере | Ответ ограничивается достижимым числом страниц, без ошибки |
| Релиз без мастера → «Версии» | Пустой список версий |
| Релиз без мастера и без главного артиста → «Похожие» | Пусто |
| Сервис дискографии недоступен | Прокси Nuxt отдаёт «сервис временно недоступен» (503); фронт показывает скелетон/пустое состояние |
| Несуществующий id релиза в блоке «Похожие» | Прокси отдаёт 404 (остальные прокси в этом случае маскируют ошибку как 503) |
| Запрос к API дискографии без токена сервиса | Отклоняется (401/403) |
| Каталог товаров недоступен | «N продавцов» = 0, разделы отдаются |
| Битые строки в дампе (повреждённый UTF-8/сжатие) | Реиндексация переходит на построчную загрузку, битые записи пропускаются и логируются; часть фасетов может страдать |

## Правила и особенности

- Обложки появляются не мгновенно — догружаются при заходе на карточку (см. «Обложки»).
- У **лейблов** нет фильтра по стране; избранное лейбла — только с его карточки.
- На поисковом драйвере точное «всего найдено» считается в обход лимита движка (через булев фасет наличия миниатюры).
