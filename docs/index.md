## Как устроена документация

Спецификация процессов MUZILLA — единый источник, по которому **согласуется флоу** и проходит **тестирование**. Живёт в репозитории (Markdown) рядом с кодом.

Принцип: **одна тема — одна страница**. Каждый процесс описан один раз, целиком — включая **сценарии тестирования прямо на странице процесса** (отдельного раздела «Тестирование» нет).

| Раздел | Что внутри |
|---|---|
| **О проекте** | площадка, роли, справочник статусов, глоссарий, список «К согласованию» |
| **Процессы** | подробный флоу по каждому разделу (Заказы, Работа с товарами, Оплата, Доставка…) — что согласуем и как тестируем |
| **Приложение · Техническая справка** | endpoint'ы, хранение данных, консольные команды — для разработчиков |

> Каждая страница процесса построена одинаково: назначение и роли → пошаговый флоу (со скриншотами) → экраны и действия → статусы и правила → риски → **сценарии тестирования** → ссылка на техническую справку.

## Статус готовности разделов

Кружок слева от раздела в оглавлении показывает этап его готовности:

- ⚪ **Серый** — раздел в работе у разработчиков: дорабатываем и перепроверяем содержимое. Как только раздел готов — он становится красным.
- 🔴 **Красный** — согласование ТЗ с заказчиком
- 🟠 **Оранжевый** — утверждён, тестируется разработчиками
- 🟡 **Жёлтый** — публичный тест пользователями
- 🟢 **Зелёный** — раздел протестирован

Сейчас все разделы — **на этапе согласования** (🔴).
