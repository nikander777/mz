# MUZILLA — План тестирования портала

**Версия:** Demo / Pre-release
**Адрес тестовой площадки:** dev.muzilla.ru

---

## 1. О чём этот документ

Документ описывает функциональные блоки портала MUZILLA, готовые к тестированию, ключевые сценарии для проверки и правила оформления найденных замечаний. Документ адресован команде тестирования; технические детали (инфраструктура, деплой, инструменты разработки) сюда не входят.

---

## 2. Важно — особенности тестовой сборки

Тестируется демонстрационная сборка портала. Часть данных и интеграций намеренно работает в демо-режиме, поскольку для оценки функционала это не критично:

- **Дискография** (раздел «Артисты», «Релизы», «Мастера», «Лейблы») — каталог структурно готов, контентное наполнение из внешней базы Discogs будет произведено отдельно, перед боевым запуском. На время тестирования разделы могут отображаться пустыми или с ограниченным набором карточек.
- **Фотографии пользователей** (аватары) — не загружены в тестовую базу. Все профили отображаются с дефолтной иконкой. Функционал загрузки и отображения аватара работает (его можно проверить через настройки личного кабинета).
- **Фотографии товаров маркетплейса** — большая часть карточек товаров идёт без изображений, поскольку данные сгенерированы для демонстрации логики. Сама механика загрузки фото в карточку товара функциональна и доступна для проверки в кабинете продавца.
- **Email-уведомления** приходят на указанную почту — на стенде подключён реальный SMTP.
- **Оплата** работает в режиме тестовой интеграции с платёжной системой Moneta. Реальные списания не производятся. Сценарий «успешной оплаты» и «отказа» доступны для прохождения сквозного флоу заказа.
- **Расчёт доставки Почтой России** работает по реальному публичному API (стоимость и сроки).

Эти ограничения сборки **не являются ошибками** — пожалуйста, не фиксируйте их как баги.

## 3. Доступ к тестовой площадке

**URL портала:** dev.muzilla.ru

### Способ 1. Самостоятельная регистрация (рекомендуется для проверки полного флоу)

1. Откройте главную страницу портала.
2. Нажмите «Войти» → «Зарегистрироваться».
3. Заполните форму.
4. Получите код подтверждения (см. ниже — в тестовой сборке код отображается напрямую).
5. Подтвердите номер, заполните имя.
6. После регистрации доступны: каталог, корзина, личный кабинет покупателя.
7. Для проверки кабинета продавца — перейдите в «Профиль» → «Стать продавцом» и пройдите анкету продавца.

### Способ 2. Готовые тестовые аккаунты (опционально)

Для проверки ролей подготовлены тестовые аккаунты (покупатель, продавец, администратор) с подтверждёнными телефоном и email — вход по логину/паролю без SMS-кода. **Доступы предоставляются по запросу.**

- Аккаунт «Продавец» уже имеет статус продавца — кабинет продавца доступен сразу.
- Аккаунт «Администратор» имеет доступ к разделу `/admin` со всеми правами модерации.

### Поддерживаемые браузеры

Тестирование рекомендуется проводить в актуальных версиях Яндекс.Браузер, Chrome, Safari, Firefox и Edge. Мобильная версия доступна по тому же URL — портал адаптивен.

## 4. Функциональные блоки и сценарии тестирования

### 4.1. Регистрация и авторизация

**Что доступно:**
- Регистрация по номеру телефона с подтверждением через SMS-код.
- Вход в личный кабинет по номеру телефона.
- Авторизация через VK ID (вход и регистрация через сервис VK).
- Восстановление доступа (повторная отправка кода).
- Подтверждение телефона при первой авторизации через VK.
- Выход из учётной записи.
- Защита маршрутов: гостям недоступен личный кабинет, авторизованным — недоступны страницы входа/регистрации.

**Ключевые сценарии:**
1. Зарегистрироваться по номеру телефона, пройти подтверждение кодом, попасть в личный кабинет.
2. Выйти и войти повторно — убедиться, что данные сохранены.
3. Войти через VK ID, проверить, что профиль создан корректно.
4. Попытаться перейти на `/profile` без авторизации — должна быть переадресация на вход.
5. Попытаться ввести неверный код подтверждения — проверить сообщение об ошибке.

---

### 4.2. Главная страница

**Что доступно:**
- Шапка с поиском, корзиной, иконками личного кабинета и избранного.
- Баннерный блок (управляется из админки).
- Подборки товаров: «Новинки», «Популярное», «Рекомендуем».
- Блок новостей.
- Категории каталога.
- Подвал с навигационными ссылками и юридической информацией.
- Адаптивная мобильная версия с нижней панелью навигации.

**Ключевые сценарии:**
1. Открыть главную страницу, убедиться в корректной загрузке всех блоков.
2. Воспользоваться поиском по сайту.
3. Перейти из баннера / подборки в карточку товара.
4. Открыть мобильную версию (или эмуляцию мобильного), проверить навигацию.

---

### 4.3. Каталог товаров

**Что доступно:**
- Категории: Винил, CD, Кассеты, DVD, HiFi-техника.
- Фильтрация: по жанру, стране, году выпуска, состоянию, цене, продавцу.
- Сортировка: по цене, новизне, рейтингу продавца.
- Пагинация и постраничная загрузка.
- Хлебные крошки и навигация по категориям.
- Боковая панель фильтров с возможностью сброса.

**Ключевые сценарии:**
1. Открыть категорию «Винил», применить фильтр по жанру и цене, проверить результат.
2. Отсортировать товары по цене (по возрастанию и убыванию).
3. Сбросить все фильтры — список товаров должен вернуться к исходному.
4. Перейти между категориями через меню и хлебные крошки.

---

### 4.4. Карточка товара

**Что доступно:**
- Галерея изображений товара (в demo-сборке у большинства карточек изображения отсутствуют — это ожидаемо).
- Описание, состояние, характеристики (формат, год, лейбл, штрих-код и т.п.).
- Цена, кнопка «В корзину».
- Информация о продавце: имя, рейтинг, ссылка на профиль продавца, кнопка «Написать продавцу».
- Блок «Похожие товары».
- Кнопка «В избранное».
- Отзывы на товар.

**Ключевые сценарии:**
1. Открыть карточку товара, добавить товар в корзину.
2. Добавить товар в избранное (для авторизованного пользователя).
3. Перейти на профиль продавца из карточки товара.
4. Нажать «Написать продавцу» — должно открыться окно сообщений.
5. Оставить отзыв на товар (после завершения заказа).

---

### 4.5. Корзина и оформление заказа

**Что доступно:**
- Добавление/удаление товара, изменение количества.
- Группировка товаров по продавцу (формируется отдельный заказ по каждому продавцу).
- Расчёт стоимости товаров и доставки.
- Выбор способа доставки: пункт выдачи / курьерская / Почта России.
- Выбор адреса доставки из сохранённых или ввод нового.
- Выбор способа оплаты: банковская карта, СБП, сохранённый способ оплаты.
- Применение промокода (если активирован администратором).
- Оплата заказа через тестовый шлюз Moneta.
- Страница результата оплаты.

**Ключевые сценарии:**
1. Добавить 2–3 товара от разных продавцов в корзину, перейти к оформлению — заказы должны разделиться по продавцам.
2. Изменить количество товара в корзине, проверить пересчёт итога.
3. Удалить товар из корзины.
4. Выбрать способ доставки «Пункт выдачи» — должны отобразиться доступные пункты выдачи на карте/списком.
5. Выбрать способ доставки «Почта России» — должна рассчитаться стоимость и срок (реальные данные API).
6. Оформить заказ с оплатой картой через тестовый шлюз — пройти сценарий «успешной оплаты».
7. Проверить, что заказ появился в личном кабинете в статусе «Оплачен».

---

### 4.6. Личный кабинет покупателя

**Что доступно:**
- Главная страница профиля: персональные данные, фото, email, телефон.
- Раздел «Мои заказы»: список заказов, детальный просмотр заказа, статусы (создан, оплачен, в обработке, в пути, доставлен, отменён), история статусов, кнопки взаимодействия с продавцом.
- Раздел «Избранное»: товары, артисты, релизы, продавцы (полиморфная система избранного).
- Раздел «Адреса»: создание/редактирование/удаление адресов доставки.
- Раздел «Моя коллекция»: каталог собственной коллекции пользователя.
- Раздел «Отзывы»: отзывы, оставленные пользователем.
- Раздел «Финансы»: история операций, возвраты.
- Раздел «Чёрный список»: заблокированные продавцы.
- Раздел «Настройки»: смена email, телефона, пароля, настройки уведомлений.

**Ключевые сценарии:**
1. Открыть профиль, проверить отображение персональных данных.
2. Изменить имя/email, сохранить, перезагрузить страницу — изменения должны сохраниться.
3. Добавить адрес доставки, отметить его основным, отредактировать, удалить.
4. Добавить товар в избранное из каталога — проверить появление в разделе «Избранное».
5. Открыть детальную страницу заказа, проверить корректность статуса и истории.

---

### 4.7. Кабинет продавца (C2C)

**Что доступно:**
- Регистрация продавца через анкету (персональные данные, паспорт, реквизиты для выплат).
- Привязка реквизитов для приёма выплат (банковская карта / СБП).
- Главная страница кабинета продавца со статистикой.
- Раздел «Мои товары»: список товаров, создание/редактирование/удаление, загрузка фотографий, управление наличием.
- Раздел «Заказы»: список входящих заказов, смена статуса, формирование отправления, печать ярлыков.
- Раздел «Финансы»: история выплат, баланс, вывод средств.
- Раздел «Статистика»: продажи, просмотры товаров, конверсия.
- Раздел «Отзывы»: отзывы покупателей на продавца.
- Раздел «Настройка доставки»: подключение перевозчиков, параметры отправлений.
- Раздел «Чёрный список»: блокировка нежелательных покупателей.

**Ключевые сценарии:**
1. Перейти в «Стать продавцом» из личного кабинета, заполнить анкету.
2. Добавить новый товар: заполнить категорию, описание, состояние, цену, загрузить фотографии (можно загрузить любые тестовые изображения для проверки механики).
3. Просмотреть свой товар на витрине от лица покупателя.
4. Получить тестовый заказ (через второй аккаунт покупателя) и обработать его: подтвердить, сменить статус на «отправлен».
5. Заполнить реквизиты для выплат.

> **Примечание:** анкеты продавца на физлица и юрлица проходят через несколько шагов с разной структурой данных. Тестирование заполнения каждого варианта — отдельный сценарий.

---

### 4.8. Профиль продавца (публичный)

**Что доступно:**
- Открытая витрина продавца с его товарами.
- Информация о продавце: имя, описание, рейтинг, география.
- Отзывы покупателей.
- Кнопка «Написать продавцу».
- Подписка на продавца (добавление в избранное).

**Ключевые сценарии:**
1. Открыть профиль продавца из карточки товара.
2. Просмотреть товары продавца.
3. Прочитать отзывы и оценить общую структуру страницы.
4. Написать сообщение продавцу через кнопку контакта.

---

### 4.9. Сообщения между пользователями

**Что доступно:**
- Список диалогов с другими пользователями (покупателями, продавцами, поддержкой).
- Чат-окно с историей сообщений, отметкой «прочитано», временными метками.
- Отправка вложений (изображения).
- Уведомление о новом сообщении в шапке сайта.
- Реальное время (новые сообщения появляются без перезагрузки страницы).

**Ключевые сценарии:**
1. С аккаунта покупателя написать сообщение продавцу из карточки товара.
2. С аккаунта продавца открыть раздел «Сообщения», увидеть новое сообщение, ответить.
3. Прикрепить изображение к сообщению.
4. Проверить корректность отображения статусов «прочитано».

---

### 4.10. Отзывы

**Что доступно:**
- Отзывы на товары и продавцов.
- Возможность оставить отзыв после получения заказа.
- Модерация отзывов на стороне администратора.
- Отображение средней оценки и количества отзывов.

**Ключевые сценарии:**
1. Оставить отзыв на товар из завершённого заказа.
2. Оценить продавца (рейтинг + текст отзыва).
3. Просмотреть свои отзывы в личном кабинете.

---

### 4.11. Новости и блог

**Что доступно:**
- Лента новостей с пагинацией.
- Категории и теги новостей.
- Детальная страница новости с медиа-контентом.
- Раздел «Блог» с подборкой материалов.

**Ключевые сценарии:**
1. Открыть ленту новостей, перейти в детальную страницу.
2. Отфильтровать по категории / тегу.

---

### 4.12. Дискография (`/disco`)

**Что доступно:**
- Структура каталога: артисты, релизы, мастера, лейблы.
- Карточка артиста / релиза / мастера / лейбла со всеми связями.
- Фильтрация и поиск по дискографии.

**Примечание:** контентное наполнение каталога Discogs произведено на портал new.muzilla.ru

---

### 4.13. Статические страницы

**Что доступно:**
- О компании, Карьера, Контакты, Помощь, FAQ.
- Юридические страницы: Пользовательское соглашение, Политика конфиденциальности, Cookies, Возвраты, Доставка.
- Партнёрская программа.
- Информация для продавцов: «Как продать», «Гид продавца».

**Ключевые сценарии:**
1. Открыть каждую страницу из подвала сайта — убедиться, что страница открывается и контент читаем.

---

### 4.14. Адаптивность (мобильная версия)

**Что доступно:**
- Адаптивная вёрстка под мобильные устройства (320–768px), планшеты (768–1024px), десктоп (от 1024px).
- Мобильное меню с бургер-навигацией.
- Нижняя панель навигации на мобильной версии.

**Ключевые сценарии:**
1. Открыть портал на смартфоне или в режиме эмуляции мобильного устройства (DevTools).
2. Пройти основные сценарии: каталог → карточка → корзина → оформление.
3. Проверить работу мобильного меню и нижней панели.

---

### 4.15. Административная панель

> Тестируется при наличии доступа администратора. Этот раздел тестируется в последнюю очередь и может содержать большее количество ошибок.

**Что доступно:**
- Дашборд с ключевыми метриками.
- Управление пользователями: список, поиск, фильтрация, детальная карточка, изменение ролей, блокировка.
- Управление товарами: список, модерация, редактирование, удаление.
- Управление заказами: список, фильтры, детальная карточка, смена статусов.
- Управление отзывами: модерация, скрытие.
- Управление новостями и блогом: CRUD по новостям, категориям, тегам.
- Управление баннерами: создание, редактирование, расписание показа.
- Управление категориями и подкатегориями каталога.
- Управление ролями и правами доступа.
- Системные настройки портала.
- Лог активности администратора.
- Уведомления администратора.

**Ключевые сценарии:**
1. Создать нового пользователя, назначить ему роль.
2. Заблокировать пользователя, проверить, что он не может войти.
3. Опубликовать новость с категорией и тегами.
4. Создать баннер для главной страницы, установить расписание показа.
5. Сменить статус заказа из админки, проверить отображение у покупателя/продавца.
6. Промодерировать отзыв (одобрить / отклонить).

## 5. Формат отчёта об ошибке

Все найденные замечания заносятся в общую таблицу Google Sheets:

**Ссылка на таблицу:** ссылка

### Структура записи

| Поле | Описание |
|------|----------|
| **№** | Порядковый номер замечания |
| **Дата** | Дата обнаружения (ДД.ММ.ГГГГ) |
| **Тестировщик** | Имя/ник того, кто нашёл ошибку |
| **Раздел** | Раздел портала (например: «Корзина», «Кабинет продавца → Товары») |
| **URL страницы** | Полный адрес страницы, где найдена ошибка |
| **Заголовок** | Краткое описание сути ошибки (1 строка) |
| **Шаги воспроизведения** | Пошаговое описание: 1) … 2) … 3) … |
| **Ожидаемый результат** | Что должно произойти |
| **Фактический результат** | Что реально произошло |
| **Критичность** | Блокирующая / Высокая / Средняя / Низкая |
| **Окружение** | Браузер + версия, ОС, тип устройства (десктоп/мобильный) |
| **Аккаунт** | Роль и идентификатор тестового аккаунта (покупатель/продавец/админ) |
| **Скриншот / видео** | Ссылка на загруженный файл (Google Drive / любой облачный сервис) |
| **Статус** | Новая / В работе / Исправлено / Закрыто / Отклонено |
| **Комментарий** | Любая дополнительная информация |

### Уровни критичности

- **Блокирующая** — невозможно выполнить ключевой сценарий (не работает регистрация, не оформляется заказ, не загружается главная).
- **Высокая** — функционал работает некорректно, но есть обходной путь (ошибка в расчёте суммы, не сохраняется адрес).
- **Средняя** — некритичные ошибки логики или интерфейса (неверный текст ошибки, поле не валидируется).
- **Низкая** — косметика: вёрстка, опечатки, мелкие визуальные несоответствия.

## 6. Что не нужно фиксировать как баг

Чтобы избежать повторных замечаний, ниже перечислены ожидаемые особенности тестовой сборки:

- Отсутствие фотографий у большинства карточек товаров маркетплейса.
- Отсутствие аватаров у пользователей (отображается дефолтная иконка).
- Пустые или малозаполненные разделы дискографии (`/disco`).
- SMS-код приходит на реальный телефон через боевой сервис SMS-рассылки.
- Оплата проходит через тестовый шлюз без реального списания средств.
- Список пунктов выдачи и стоимость курьеров (кроме Почты России) — демонстрационные.
